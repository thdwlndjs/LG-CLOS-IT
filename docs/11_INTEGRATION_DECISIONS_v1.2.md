## B. 이번에 추가 확정한 세부 정책 (ADR-09~13)

| ID | 확정 정책 | 데이터·UX 규칙 |
|---|---|---|
| ADR-09 계정·프로필·기기 연속성 | **하나의 물리적 옷장에 전체 의류를 통합**. 개인 프로필로 사용자를 식별하며, 다른 매장/스마트미러에서도 로그인하여 같은 옷장 데이터와 자신의 코디·기록을 불러옴 | 의류 목록은 프로필 소유자별로 분리하지 않음. 코디·착용 이력 등 개인화 데이터는 `member_id` 기준. `device_id`는 물리 스마트 옷장의 식별자이며, `household_id`는 기존 DB의 가구 범위로 호환 유지한다. 의류는 물리 보관 기기 `device_id`로 연결한다. 별도 ‘공유 의류/공유 권한’ 기능 금지. 다른 미러 로그인에 필요한 **실제 계정 인증·기기 신뢰·세션 연속성**은 기존 계약으로 달성되는지 검증 필요 |
| ADR-10 의류 속성 최소화 | 카테고리·색상·이미지 등 **실제로 사용되는 정보만** 관리. 브랜드·사이즈를 신규 필수 수집·적재 항목으로 만들지 않음 | 현재 DDL의 필수 `category`·`color`는 유지해 호환성을 확보. `image_asset_id`는 현 계약상 선택. 이름/브랜드/사이즈를 필수화하거나 브랜드·사이즈 전용 컬럼을 신설하지 않음. 위치·상태·관측은 기존 Digital Twin 데이터로 관리. URL/원본 키는 필요한 동기화·중복방지용 내부 식별 참조에 한정 |
| ADR-11 코디 확정은 조명만 작동 | **코디 확정 → 해당 보관 칸 LED 점등**. 착용 예정 등록은 별도 사용자 행동, 실제 착용 확인도 별도 | 확정만으로 plan·wear 이벤트 생성 금지. VTON 세션 종료/최종 선택 정보는 기존 계약의 의미 유지. 캘린더 ‘착용 예정’ 별도 저장 계약은 기술 검토 대상 |
| ADR-12 조명 소등 정책 | **찾기·코디 확정 → 해당 칸 점등 → 일정 시간 뒤 자동 소등**, 다중 칸 대상 지원 | 소등 시간은 설정 가능한 값으로 정의하되 구체 초/분 수치는 임의 확정 금지. 위치 UNKNOWN/STALE 임의 점등 금지. **집과 다른 외부 스마트미러에서 조회 시 집의 물리 LED가 원격 점등되지 않도록 기기·컨트롤러 범위 검증** |
| ADR-13 구매 내역 일괄 등록 | **전체 구매 내역 불러오기 → 한 번의 사용자 일괄 등록 액션으로 옷장 반영** | 각 상품별 선택·확인 절차를 필수로 두지 않음. 이미 등록된 품목/취소·반품 등 부적합·정보 불충분 품목은 자동으로 성공 처리하지 않고 항목별 `SKIPPED`/`NEEDS_REVIEW`/`FAILED` 표시. 일괄 등록 명령의 명시적 실행과 ‘구매만으로 실제 보유를 증명한다’는 주장을 구분. Mock 구매활동은 **합성 자료**로 표시 |

## C. 기기 단위 물리 옷장·개인 데이터 분리 원칙

- 하나의 물리적 스마트 옷장 = 하나의 `device_id`. 해당 기기에 속한 `garment`, `garment_state`, `storage_location`을 공통 조회한다. 기존 `household`/`household_id`는 호환성과 계정-가구 관계를 위해 유지하며, 물리 기기 ID로 혼용하지 않는다.
- `member` → 로그인 식별자 및 개인 코디(`outfit`), VTON 세션, 착용 이력, 개인 설정, 쇼핑 계정 연결의 스코프. 다른 기기에서 동일한 구성원 계정으로 조회 가능해야 함.
- 기존 DB의 `garment.owner_id NOT NULL`과 기존 API `owner_id` 쿼리는 **단일 옷장 정책과 의미 충돌**. 기존 `owner_id`는 유지한다. 신규 `garment.device_id`를 물리 옷장 소속 기준으로 사용하고, 접근 가능한 `device_id` 전체 의류를 조회한다. 기존 `household_id`도 유지하여 기존 인가 경계를 보존한다. `owner_id` 기본 필터로 목록을 제한하지 않는다.
- 가정용 칸별 조명은 가구 옷장 *위치*에 연결. 다른 매장 미러에서는 데이터/VTON을 사용하되 **해당 집의 물리 컨트롤러 제어를 호출하지 않음**.

## D. 이번에 기존 초안에서 폐기·수정한 주장

1. ‘프로필별 독립 옷장’ 및 ‘개인/공유 의류 구분’ → **폐기**. 프로필을 전환해도 같은 가구의 전체 의류가 보인다.
2. ‘브랜드·사이즈 추가 적재/DTO 확장’ → **요구사항에서 제거**. 이식 원본이 포함하더라도 기능에서 소비하지 않으면 저장하지 않음. 기존 `material`, care 관련 데이터 제거를 뜻하지 않음.
3. ‘코디 확정 시 착용 예정 저장’ → **폐기**. 코디 확정은 LED, 계획은 별도 행동.
4. ‘구매 내역 선택 가져오기/항목별 보유 확인’ → **일괄 등록**으로 대체. 단, 검증 실패 항목을 성공으로 둔갑시키지 않음.
5. GAP-09 일반 웹 반응형 재설계 → **미채택**. 팀원 구현값을 비교 기준으로 사용.
6. ‘원격 기기 로그인으로 집 LED도 자동 제어’ → **요구사항 아님**. 기기 위치와 권한을 구분.

## E. 계약 리뷰로 넘길 사항 (정책 확정과 다름)

- **C-01** 기존 `garment.owner_id`를 유지하면서 신규 `garment.device_id`를 추가하고, 사용자-기기 연결(`device_member`) 및 기존 `household_id` 인가와 정합성 검증.
- **C-02** 현재 `/api/v1/sessions`가 `household_id`·`member_id`로 세션을 시작하는 수준에서 **다른 매장 로그인/동일 계정 식별**까지 보장하는지.
- **C-03** 코디 최종 선택(`/vton-sessions/{id}/end`)과 별도 착용 예정 저장 API·원장의 부재.
- **C-04** `storage_location`에 대한 실제 LED 구역 매핑/제어 인터페이스와 **기기별 로컬 제어 범위** 부재.
- **C-05** 기존 쇼핑 설계의 선택/확인 API와 일괄 import·항목별 실패 정책 충돌; 카탈로그·옵션의 과설계 제거.
- **C-06** 팀원 의류 등록 UX(사진/이름 필수, 색상 선택)와 기존 garment 요청 DTO(category/color/owner 필수)의 불일치.
- **C-07** 다른 기기에서 동일 이미지 접근을 위한 기존 private asset 서명/세션·동의 정책 검증.

각 항목의 증거와 변경 후보는 `14_CONTRACT_CONFLICT_REVIEW_v0.1.md` 참조. 여기서 확정되지 않은 기술 계약을 임의로 기존 OpenAPI/DDL에 적용하지 않는다.


## 기기 식별 모델 변경 결정 (이번 개정에서 우선 적용)

- **확정:** `user_id`/기존 `member_id`는 사람과 개인화 자료를 식별한다. **`device_id`는 집의 물리적 스마트 옷장을 식별한다.** `garment.owner_id`는 기존 컬럼으로 유지하고 `garment.device_id`를 추가한다. `device_member`(명칭은 구현 시 기존 관계 모델과 충돌 확인)로 접근 가능한 사용자와 옷장을 연결한다.
- **조회:** 같은 물리 옷장에 연결된 구성원은 `owner_id`와 관계없이 해당 `device_id`의 모든 의류를 본다. 코디·착용 기록 등 개인 자료는 기존 `member_id` 범위를 유지한다.
- **외부 매장:** 매장의 미러 기기는 **접속 기기**이고, 집의 `device_id`는 **보관 기기**다. 로그인으로 접근 권한을 확인한 뒤 집 옷장 데이터를 불러오되, 매장에서는 집 LED 제어 명령을 실행하지 않는다. 두 종류의 기기 ID를 혼용하지 않는다.
- **호환:** 기존 `household`/`household_id`를 즉시 삭제·대체하지 않는다. 이미 존재하는 FK, API, 권한 경계를 보존하면서 물리 옷장 식별자와 매핑한다. 기존 의류에 대한 `device_id` 백필 방법은 실제 데이터 확인 후 확정한다.
- **미확정 기술 세부:** 기기 등록·인증 방법, `device_member`의 실제 테이블명과 PK/FK, 다중 기기 소유 시 선택 UX, 조명 컨트롤러의 인증 방식. 제품 요구로 임의 추가하지 않는다.
- **변경 금지:** 팀원 프론트의 옷장 구조·중앙 미러 크기·비율·좌표·컴포넌트 규격. 구매 일괄 등록·좋아요 VTON 한정·코디 확정 시 조명만·자동 소등 등 기존 확정사항 유지.

> 본 개정의 기기 식별 정책이 이전 본문에 남아 있는 ‘household가 물리 옷장 ID’ 또는 ‘owner_id 삭제 검토’ 표현보다 우선한다. 실제 API/DDL 구현은 코드 검증 후 별도 승인한다.
