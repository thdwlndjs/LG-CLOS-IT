## 2. 중앙 미러 UX 고정 사항

1. 좌우 옷장 영역/중앙 스마트미러/LED 표시 칸의 배치, 중앙 UI 폭, 구성 요소의 시각적 규격을 팀원 구현값으로 고정한다. 문서가 임의 수치나 새 CSS 값을 지정하지 않는다.
2. Mock LED 점등 표현은 팀원 기존 칸 위치 매핑에 연결한다. 조명은 실제 위치조회·제어 작업의 결과를 시각적으로 반영해야 하며 CSS 애니메이션만으로 성공 처리하지 않는다.
3. 원본 QA 1920×1080 데스크톱 캡처와 같은 viewport에서 변경 전/후 시각 회귀 테스트 수행. 미러 내부 추가 UI 때문에 원형 비율을 변경하지 않는다.
4. 모바일 390px에서의 기존 겹침 판정은 보존하되, 이번 제품 합격 조건을 임의로 일반 모바일 반응형으로 확대하지 않는다.

## 3. 핵심 인수 시나리오

1. 집 미러 프로필 A 로그인 → **A/B 소유 구분 없이 가구 전체** 의류 조회 → A 코디 이력 조회.
2. 외부 매장 미러에서 A 인증 → 동일 가구 의류·A 코디/기록 조회 → VTON 사용 → **집 LED 원격 제어 0회**.
3. 프로필 B로 전환 → 가구 의류 목록 유지, **개인 코디와 실제 착용 기록**은 B 기준.
4. 코디 확정 → 위치 확인 가능한 복수 칸 점등 → 자동 소등 → **착용 예정 0건, wear 0건**.
5. 사용자가 별도 '착용 예정' 저장 → plan 1건(계약 확정 후) → wear 0건.
6. 별도 '실제로 입었음' 확인 → wear 1건; 중복 요청 방지.
7. Mock 구매 목록 10건 예시 → 일괄 등록 1회 → 중복/취소/누락은 개별 상태 표기 → 성공 품목만 공통 옷장에 반영. 10건 전량 성공이라는 가정 금지.
8. LIKED 상품 VTON → 개인 결과 조회, garment/wear/outfit/card 자동 생성 0건.
9. 동일 viewport의 팀원 UI 시각 회귀 통과. 단순 버튼 노출이 아니라 API/상태/오류 동작 확인.

## 4. 기술 계약 미확정

- 실제 다른 매장 미러 로그인 인증과 trusted-device 경계, token 취급, 사용자→가구 조회 계약.
- `garment.owner_id` 유지 + `garment.device_id` 추가 + 사용자-기기 연결 및 의류 조회·등록 DTO 정합성.
- 계획 저장 API/DB(개인 `member_id` 및 날짜/타임존), 취소/수정.
- 조명 구역 식별자·명령 API·자동 소등 기본값/기기 범위.
- 일괄 import의 항목별 상태 모델, 취소·반품·기등록 중복 처리.
- 카드 공유 범위/만료, 실제 디스플레이 해상도, 팀원 제공 자산 사용 조건.

이 기술 미확정 항목은 **기능을 임의 확정할 근거가 아니며**, `13_BACKEND_CHANGE_SPEC_DRAFT_v0.2.md`, `14_CONTRACT_CONFLICT_REVIEW_v0.1.md`에서 선행 검증한다.


## 기기 식별 모델 변경 결정 (이번 개정에서 우선 적용)

- **확정:** `user_id`/기존 `member_id`는 사람과 개인화 자료를 식별한다. **`device_id`는 집의 물리적 스마트 옷장을 식별한다.** `garment.owner_id`는 기존 컬럼으로 유지하고 `garment.device_id`를 추가한다. `device_member`(명칭은 구현 시 기존 관계 모델과 충돌 확인)로 접근 가능한 사용자와 옷장을 연결한다.
- **조회:** 같은 물리 옷장에 연결된 구성원은 `owner_id`와 관계없이 해당 `device_id`의 모든 의류를 본다. 코디·착용 기록 등 개인 자료는 기존 `member_id` 범위를 유지한다.
- **외부 매장:** 매장의 미러 기기는 **접속 기기**이고, 집의 `device_id`는 **보관 기기**다. 로그인으로 접근 권한을 확인한 뒤 집 옷장 데이터를 불러오되, 매장에서는 집 LED 제어 명령을 실행하지 않는다. 두 종류의 기기 ID를 혼용하지 않는다.
- **호환:** 기존 `household`/`household_id`를 즉시 삭제·대체하지 않는다. 이미 존재하는 FK, API, 권한 경계를 보존하면서 물리 옷장 식별자와 매핑한다. 기존 의류에 대한 `device_id` 백필 방법은 실제 데이터 확인 후 확정한다.
- **미확정 기술 세부:** 기기 등록·인증 방법, `device_member`의 실제 테이블명과 PK/FK, 다중 기기 소유 시 선택 UX, 조명 컨트롤러의 인증 방식. 제품 요구로 임의 추가하지 않는다.
- **변경 금지:** 팀원 프론트의 옷장 구조·중앙 미러 크기·비율·좌표·컴포넌트 규격. 구매 일괄 등록·좋아요 VTON 한정·코디 확정 시 조명만·자동 소등 등 기존 확정사항 유지.

> 본 개정의 기기 식별 정책이 이전 본문에 남아 있는 ‘household가 물리 옷장 ID’ 또는 ‘owner_id 삭제 검토’ 표현보다 우선한다. 실제 API/DDL 구현은 코드 검증 후 별도 승인한다.
