# 모바일 미러 반응형 추가 변경 지시서

## 1. 목적과 범위

데스크톱에서는 현재 좌우 물리적 옷장과 중앙 스마트미러 원본 레이아웃을 유지한다. 모바일 세로 화면에서는 좌우 옷장 배경을 표시하지 않고 미러 디스플레이가 화면 전체를 채우도록 한다. 신규 UI 디자인이나 기능 기획이 아니라 기존 미러 UI의 표시 영역을 반응형으로 확장하는 작업이다.

이 문서는 구현 지시서이며, 작성 시점에는 반응형 코드를 변경하지 않았다. 사용자의 이번 요청은 기존 SECOND_HANDOFF_PLAN의 모바일 재설계 금지에 대한 제한적인 추가 요구사항이다. 원본 설계 문서와 팀원 공유본은 수정하지 않는다.

## 2. 현재 코드와 실제 화면 확인

2026-10-10 로컬 Vite 화면을 Playwright Chromium에서 실행해 확인했다.

| 뷰포트 | 전체 사진 영역 | 중앙 미러 영역 | 현재 문제 |
|---|---|---|---|
| 1672×941 | 1672×941 | x=714, y=28, 248×824 | 데스크톱 기준 화면, 유지 대상 |
| 390×844 | 약 390×219.5 | x≈166.5, y≈318.8, 57.8×192.2 | 전체 사진 축소로 미러까지 작아지고 위아래 공간이 크게 남음 |

근거: `PhotoWardrobeStage.tsx`의 ResizeObserver는 `min(viewportWidth/1672, viewportHeight/941)`로 전체 사진을 맞춘다. 미러는 사진 안의 고정 비율 좌표로 배치된다. `.photo-wardrobe`는 화면을 채우지만 `.photo-stage`와 미러는 함께 축소된다. 현재 모바일 화면 캡처는 로컬 미추적 증적 `test-results/mobile-before-responsive.png`에 있다. 이는 데스크톱 Chromium의 모바일 크기 확인이며 실제 iOS/Android 기기 검증은 아니다.

## 3. 적용 규칙

- 구현 시작값은 **CSS 뷰포트 폭 767px 이하**에서 모바일 미러 모드, **768px 이상**에서 기존 원본 모드로 한다. 장치명·User Agent·터치 여부로 분기하지 않는다. 데스크톱의 좁은 창도 같은 규칙을 따른다.
- 모바일 가로 화면도 폭 기준을 적용한다. 폭 767px 이하이면 미러 모드를 유지하며 낮은 높이에 스크롤로 대응한다. 768px 이상이면 기존 원본 모드다. 별도 태블릿·가로 화면 재설계는 하지 않는다.
- 모바일에서는 미러 컨테이너가 사용 가능한 뷰포트의 폭·높이를 채운다. 원본 미러 종횡비 248:824를 고정하여 여백을 남기지 않는다. 화면 전체를 채우는 대상은 미러 외곽 영역이며, 내부 콘텐츠는 필요한 경우 세로 스크롤로 접근한다.
- 데스크톱의 이미지, 좌표, 비율, 크기, LED 기준점과 원본 CSS 결과를 변경하지 않는다. 공통 규칙 수정으로 데스크톱이 달라지는 구현을 피한다.
- 표시 모드 전환으로 React 화면을 재마운트하거나 로그인·선택한 의류·코디 초안·VTON 폴링을 초기화하지 않는다.

## 5. 모바일 화면 구현 상세

### 배경과 디스플레이

1. `.photo-background`의 좌우 옷장 전체 사진과 `.photo-led-layer`를 모바일에서 비노출한다. 배경 전체 사진을 단순 cover 확대해 옷장 일부가 남는 방식은 사용하지 않는다.
2. `.photo-mirror`는 전체 폭·높이를 차지하고 모바일에서 원본 사진 좌표의 left/top 오프셋을 제거한다. 전체 장면을 transform scale로 확대하는 방식은 사용하지 않는다.
3. 미러 내부 분위기는 유지한다. 기존 미러가 투명 UI이며 배경이 별도 미러 이미지가 아닌 전체 사진이라는 점을 고려한다. 필요하면 원본 중앙 미러 영역만 잘라 전용 배경으로 사용하거나 기존 색상을 바탕으로 최소 배경을 적용한다. 좌우 옷장이 보이지 않아야 하며 새로운 이미지 생성·장식 리디자인은 하지 않는다.
4. `100dvh`와 지원 환경용 `100vh` fallback을 고려하고 주소창 높이 변화·노치·하단 제스처 영역에 대응한다. safe-area 여백은 미러 내부에 적용한다. 이 동작은 구현 후 실제 모바일 브라우저에서 확인한다.

### 내부 콘텐츠와 접근성

- 기존 헤더, 좌측 메뉴, 작업 영역의 순서와 기능을 유지한다. 메뉴를 새 하단 탭바로 바꾸지 않는다. 화면을 채우도록 필요한 폭·간격만 조정한다.
- 기존 `--mirror-width * 3.32258` 높이 산식은 원본 미러 종횡비를 가정한다. 모바일에서는 실제 컨테이너 높이나 flex/grid로 바꿔 코디 버튼·인물 결과가 화면 밖으로 밀리지 않게 한다.
- 화면 단위로 스크롤 소유자를 명확히 정한다. 메뉴·헤더를 유지하면서 작업 패널을 세로 스크롤하고, 대화상자는 자체 스크롤한다. `overflow:hidden` 때문에 하단 버튼이 접근 불가능하면 실패다.
- 로그인, 등록, 검색 등 입력창에 포커스했을 때 가상 키보드에 가려진 필드·실행 버튼까지 스크롤할 수 있어야 한다. 모바일에서 입력 폰트는 최소 16px, 주요 터치 영역은 최소 44×44px로 조정한다.
- 의류 사진·VTON·코디카드는 기존 contain 표시를 유지해 이미지 내용을 자르지 않는다. 페이지 넘김과 스와이프가 세로 스크롤을 막지 않도록 한다.
- 전체 화면 버튼은 화면을 채우는 필수 조건으로 사용하지 않는다. 일반 브라우저 상태에서도 동작해야 한다. 지원하지 않는 Fullscreen API의 기존 안내도 유지한다.
- 모바일에서 사진 LED 레이어를 숨겨도 위치 안내·LED 요청 결과는 기존 텍스트로 제공한다. 실제 LED 권한·점등·자동 소등 로직은 변경하지 않는다.

## 6. 유지할 기능 및 계약

DB·API·기기 접근 범위·인증·Signed URL·이미지 Blob 캐시를 변경하지 않는다. 최근 변경한 스타일 보관함의 `내 옷장 / 쇼핑몰` 두 탭과 전체 의류 조회를 유지한다. LIKED를 보유 의류로 자동 등록하지 않고 코디 확정을 착용 기록으로 자동 생성하지 않는다. 모바일 전환만으로 데이터 조회·Signed URL 발급·캐시된 의류 이미지 다운로드가 추가 반복되어서는 안 된다. 중앙 미러 전용 배경을 별도 정적 파일로 만들 경우 최초 로드는 허용하되 기존 원본 리소스와 브라우저 캐시를 활용하고 전환마다 재다운로드하지 않는다. 유료 API 호출과 클라우드 설정 변경은 범위 밖이다.

## 7. 구현 순서

1. 현재 데스크톱 홈·옷장·코디 화면을 기준 캡처하고 원본 모드 크기를 기록한다.
2. Stage의 모바일 모드, 배경 비노출, 전체 미러 배치를 먼저 구현한다.
3. 같은 미러 컴포넌트를 유지하면서 화면별 높이·스크롤·대화상자·터치 영역 충돌을 해결한다.
4. 아래 QA를 실행하고 실패를 수정한다. 미실행 항목은 별도 기록하고 완료로 처리하지 않는다.
5. `docs/integration/PROGRESS.md`에 변경 파일·결과·증적·남은 항목을 기록하고 Conventional Commit을 남긴다. 원격 배포는 기존 승인 및 배포 절차를 따른다.

## 8. 검증 및 완료 기준

| 검증 영역 | 필수 시나리오/판정 |
|---|---|
| 모바일 치수 | 360×800, 390×844, 430×932에서 미러가 사용 가능한 전체 영역을 채움. 좌우 옷장·큰 외부 여백·페이지 수평 스크롤 없음. safe-area 제외 영역은 1px 이내 오차로 확인. |
| 분기 경계 | 폭 767px와 768px에서 지정 모드가 적용되고 왕복 resize 시 상태 유지. 폭 667×높이 375도 미러 모드에서 모든 동작에 접근 가능. |
| 데스크톱 회귀 | 1366×768, 1672×941, 1920×1080에서 기존 장면 비율·미러 좌표·이미지·LED 표시 유지. 동적 시각·날짜·데이터를 고정하거나 캡처 비교에서 제외. |
| 홈/옷장 | 추천·관리 안내 및 의류 목록·사진·검색·상세 접근. 스타일 보관함에 내 옷장/쇼핑몰 두 탭, 실제 의류 전체 표시 및 선택 확인. |
| 입력/모달 | 로그인·시연 로그인·등록·편집·동의·이미지 업로드·케어 화면에서 필드와 하단 버튼 접근. 실제 모바일 키보드 열린 상태 포함. 임시 QA 등록 데이터는 구분·정리. |

| 위치/LED | 위치 안내·Mock LED 동작과 소등 유지. 모바일에서 사진 LED가 안 보여도 결과 안내 접근 가능. |
| 상태/캐시 | 로그인·초안·선택·VTON 진행 중 모바일↔데스크톱 전환 시 유지. 캐시된 사진은 전환만으로 재발급·재다운로드하지 않음. |
| 모바일 브라우저 | 실제 iOS Safari와 Android Chrome에서 주소창 변화, safe-area, 키보드, 회전 및 터치 확인. 데스크톱 에뮬레이션 결과와 구분 기록. |

실행 예: `npm test --prefix web`, `npm run build --prefix web`, 구현한 Playwright 반응형 QA 스크립트. 브라우저 캡처·치수·네트워크 기록과 실제 기기 결과를 증적으로 남긴다. 위 검증을 수행하기 전에는 모바일 반응형 구현·검증 완료라고 보고하지 않는다. 이 조건은 지시서 작성 완료와 구분한다.
