# 스마트 옷장 시연용 옷장 팩

48종의 의류·잡화 이미지와 품목 정보, 등록 사진, 정적 착장 예시를 함께 담았습니다. 압축을 푼 뒤 `index.html`을 열면 전체 품목을 검색하고 확인할 수 있습니다.

| 구성 | 수량 |
| --- | ---: |
| 상의 | 12 |
| 하의 | 9 |
| 아우터 | 8 |
| 원피스 | 1 |
| 모자 | 5 |
| 신발 | 7 |
| 가방·벨트·머플러·목걸이 | 6 |
| 등록용 촬영 예시 | 1 |
| 착장 예시 | 3 |

## 바로 사용하는 파일

- `index.html`: 인터넷 없이 열리는 품목·착장 미리보기입니다. 이름·종류·색상·계절로 검색할 수 있습니다.
- `assets/catalog/`: 48종의 개별 투명 PNG입니다. 파일명과 품목 ID가 같습니다. 예: `T07.png` = 그레이 맨투맨.
- `data/catalog.json`, `data/catalog.csv`: 품목 ID, 분류, 세부 종류, 색상, 계절, 설명, 이미지 경로를 한 행씩 연결한 목록입니다.
- `data/garments.json`, `data/assets.json`: 앱의 의류·미디어 저장 도메인에 대응할 가져오기 원본입니다. 같은 내용의 CSV도 있습니다.
- `data/outfits.json`, `data/outfit_items.json`, `data/saved_results.json`: 세 코디와 그에 해당하는 착장 이미지의 연결 정보입니다.
- `db/wardrobe_demo.sqlite`: 48품목과 연결 정보를 넣고 검증한 오프라인 시연용 DB입니다. 이미지 파일은 별도 폴더에 있습니다.
- `tools/import_pack.py`, `db/schema.sql`: 패키지 검사 및 새 오프라인 DB 생성 도구입니다. Python 3 표준 라이브러리만 사용합니다.
- `docs/DB_가져오기_안내.md`: 기존 앱 DB로 옮길 때의 필드·ID·소유자·이미지 저장 경로 연결 방법입니다.

## 시연 순서

1. `맨투맨`, `후드티`, `니트`, `슬리브리스`, `롱슬리브`를 검색해 상의 형태 차이를 확인합니다.
2. `LOOK02`의 크림 니트·인디고 데님·브라운 부츠를 선택합니다.
3. 상의와 신발을 유지하고 하의 `B03`을 `B01`로 바꾸면 `LOOK03`의 블랙 슬랙스 착장으로 연결합니다.
4. 올리브 셔츠 등록 예시 `REGISTER01`은 `T04`와 같은 의류입니다. 전체 48종을 넣은 상태라면 기존 품목 일치·중복 확인을 시연합니다. 신규 등록을 시연할 때는 시작 목록에서 T04를 제외한 별도 초기 상태를 사용합니다.

`LOOK01`은 그레이 맨투맨(T07)·조거팬츠(B07)·러닝화(S03), `LOOK02`는 니트(T05)·데님(B03)·부츠(S04), `LOOK03`은 니트(T05)·슬랙스(B01)·부츠(S04)입니다.

## 데이터의 의미

이미지와 인물은 생성된 시연 자산입니다. 착장 이미지는 미리 만든 정지 예시이며 실제 실시간 피팅 결과, 치수 검증, 특정 피팅 API의 실행 결과가 아닙니다. 선택한 인물·전체 코디·자산 버전이 일치할 때만 해당 예시를 표시합니다. 다른 조합의 결과는 준비되어 있지 않습니다.

색상·계절·스타일은 생성 의도와 외형에 따른 시연용 분류입니다. 색상 HEX는 UI용 근사값입니다. 실제 브랜드·사이즈·소재 함량·케어 라벨·물리적 보관 위치는 미확인으로 비워 두었습니다. 실제 착용·세탁·이동 기록은 생성하지 않았습니다.

샌들 S06은 수정본을 기본 이미지로 지정했습니다. 수정 전 이미지는 `history/`에만 보존하며 품목 수나 DB 등록 대상에 중복으로 포함하지 않습니다. 기존 48종 이미지는 재생성하거나 변형하지 않았습니다.

## 검증 및 새 DB 생성

압축을 푼 폴더에서 다음 명령을 실행합니다.

```bash
python tools/import_pack.py --validate-only
python tools/import_pack.py --sqlite my_demo.sqlite
```

두 번째 명령은 새 DB 파일만 만듭니다. 같은 이름의 기존 DB는 덮어쓰지 않습니다. 검수 기록은 `docs/image_validation.json`, `docs/db_validation.json`, `docs/QA_결과.md`에 있습니다. 전체 파일의 체크섬은 `checksums.sha256`에 있습니다.

이 팩의 완료 범위는 이미지·데이터·오프라인 가져오기 검증입니다. 실제 앱 DB에 업로드하거나 서비스의 계정·RLS·Storage 정책을 적용한 상태는 아닙니다.
