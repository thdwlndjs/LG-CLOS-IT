스마트 옷장 — 생활 데이터·상품 근거·기능 연결 준비팩 v0.1
2026-10-09 / scprep-20261009-v1

무엇을 했나
시연 사용자 2명의 의류 구성안 32벌, 외부 구매후보 4개, 저장 코디 18개, 생활 사건70개,
취향/좋아요9개, 날씨/사용시점4개를 서로 연결했다.
공식 상품정보 후보10건을 구조화했고, 이 중 직접 본문 확인5건/공식검색스냅샷5건을 분리했다.
8개의 의류-상품 근거 바인딩을 준비했다. 읽은 정보의 충돌과 미확인은 유지했다.
wear count·날짜·권한범위·동일상품별개소유·계획과실착·참조관계 등의 오프라인28검사를 실행했다.
기존 앱과 통합설계서는 변경하지 않았다.

가장 중요한 한계
- 32벌은 논리 구성과 이력의 초안이다. 32개의 실제 의류 사진을 확보했다는 뜻이 아니다.
- 실제 카탈로그 이미지, 인물영상, 실물 라벨 사진은 이 팩에 없다. 새 옷 그림도 생성하지 않았다.
- 공식 상품페이지는 실물라벨이 아니다. 실제 사용자 의류와 같다고 매핑하지 않았다.
- 모든 생활 이력·소유·날씨·취향은 시연 fixture다. 실제 휘재의 행동/선호 자료가 아니다.
- 운영 DB/현재 스키마/서버/앱/유료API는 이 환경에서 확인·변경·실행하지 않았다.
- 파일 형식은 logical interchange다. 현재 SQL 테이블의 직접 import 파일로 간주하지 말 것.
- source 검색/본문에는 서로 다른 회수 상태가 있다. 상품가격·재고·한국판매는 검증하지 않았다.

먼저 볼 것
review/데이터검토.html : 사람이 읽는 프로필·의류·이력·근거 요약. 새 고객 화면 시안이 아니다.
review/STATUS.json : 완료/미완료의 수량과 확인 범위.
Codex_실데이터연결_안전적재_기능검증_지시문.txt : 실제 작업환경에서 이어갈 지시.

팩의 사용 순서
1. 현재 UI작업이 진행 중이면 같은 폴더/DB를 동시에 수정하지 않는다. 별도 작업공간 또는 순차 진행.
2. 논리자료와 기대값을 읽고 현재 프로필·의류·이벤트·외부상품·자산 모델에 매핑한다.
3. data/asset_intake.json의 P0 항목부터 사진/제품원문/인물영상/권리를 연결한다.
4. 기존유사사진 이름만으로 매핑하지 않고 동일상품/변형/실물여부를 명시 확인한다.
5. 먼저 격리 DB dry-run. 실제 운영적재나 과금은 미확정된 target/asset/budget을 확인한 뒤만 진행.
6. 수진 케어·휘재 코디/피팅 정상경로를 실제로 실행하고 부족자료와 코드결함을 나누어 보고.

한 번에 재현할 오프라인 확인 (Python 3.10 이상, 추가 패키지 없음)
python tools/pack_logic.py
python -m unittest discover -s tests -v

위 명령은 로컬 JSON을 읽고 참조계산/검사만 한다. DB 연결·파일업로드·공급자호출은 하지 않는다.

대표 이력
S01 수진 베이지셔츠: 10/4세탁, 10/5·7·8 착용 -> 3회/3일. 10/8다림질은 초기화하지 않는다.
H02 휘재 블루셔츠: 10/7세탁, 10/8 오전/저녁 -> 2회/1일. 10/9계획은 실착이 아니다.
H05 화이트티: 세탁완료가 있으나 건조완료 없음. H03 맨투맨은 사용자 세탁대기 관찰.
S13처럼 자료가 없는 옷은 '안 입은 옷'으로 단정하지 않는다.

남은 핵심 자료
현재 Auth/프로필 ID와 DB스키마, 사용가능한 기존 의류사진 또는 새 실제상품 이미지,
대표 의류의 실물라벨(없으면 공식상품안내로 구분), 승인된 피팅 인물 영상,
검토된 LED 매핑, 현재 공급자/자산전송/과금 한도.
날씨는 이번에 재현 fixture만 만들었다. live 기상 조회는 앱의 실제 실행환경에서 별도 확인한다.
