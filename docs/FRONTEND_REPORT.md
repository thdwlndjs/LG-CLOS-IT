# 프론트엔드 구현·검증 및 QA 인계

판정: **프론트엔드 구현·개발자 검증·로컬 QA 기동 완료**. 2026-10-09 07:33 KST에 최종 대조를 통과했다. 사용자 직접 QA 승인은 대기한다. 실제 Decart 구현·선택 외부 연동·유료 검증은 진행하지 않았다.

## 구현 범위

[프론트 설계](FRONTEND_DESIGN.md)의 IA 여섯 메뉴와 공통 흐름을 구현했다. 홈은 Context·추천 이유·부분 집계를 표시하고, 옷장은 실제 의류 목록·필터·페이지·사진 등록·수정·삭제·공유·위치 조회·Mock 관측을 제공한다. 코디는 슬롯 편집·보관과 출처별 참고 스타일을 연결한다. 공통 입어보기는 세션·독립 구성 수정·사진 업로드·Mock 작업 polling·최종 선택을 제공하며 별도의 실제 착용 확인과 구분한다. 코디카드는 실제 Chromium 생성·비공개 저장·24시간 공유·공유 폐기·코디 재사용을 연결한다.

캘린더는 월·날짜·종류별 이력과 착용 확인/취소를 제공한다. 케어는 관리 가이드·사용자 프로필·일정 수정/취소·반복·수행/미수행·완료 취소를 지원한다. 보관은 분석 미리보기·제안 저장·승인/거절/취소·개별 실제 이동/실패 확인을 구분한다. 마이는 사진 동의/철회·동의 이력·시간대·단위·알림·미연동 상태를 제공한다. 원본 기능 28개의 프로토타입 경계를 [설계 매핑](FRONTEND_DESIGN.md)에 기록했다.

React 화면은 데스크톱 사이드 메뉴와 모바일 하단 메뉴를 제공한다. 외부 폰트/이미지를 로딩하지 않는다. 키보드 label·focus·dialog/Escape와 본문 바로가기를 제공한다. 브라우저 뒤로가기, 새로고침 시 재로그인, 401 자동 잠금, 로딩·빈 상태·실패·부분 실패·이미지 누락을 구분한다. 인증과 서명 URL은 메모리에만 두며 영구 브라우저 저장에 넣지 않는다. 변경 중 중복 클릭을 막고 네트워크 오류 재시도는 같은 요청 키를 유지한다. 충돌 시 version/revision 검사를 우회하지 않는다.

## 검증과 증적

단위 테스트 **13개 통과, 실패/skip 0**: 요청 키 재사용, 권한 오류, 충돌 version 헤더, 파일 조건, 고정 자산 중계 주소, 외부 링크 제한, 달력 경계 등을 확인했다. 최종 실제 Chromium 브라우저 시나리오 **18개 통과**, uncaught 오류 0, 외부 브라우저 요청 0이다. 테스트에서 사용한 사진은 합성 단색 PNG이며 실제 인물 사진이 아니다. backend/DB/Redis/MinIO/Celery/Chromium은 실제 실행했으며 주 DB 대신 전용 UUID DB를 사용했다. 테스트 API/worker/DB와 테스트 자산은 정리했다.

| 시나리오 | 확인한 내용 |
|---|---|
| 01~05 | 데모 프로필·홈, 동의 이력, 실제 서명 PUT/SHA256 finalize, 의류 CRUD/위치/Mock 관측/필터, Context·추천 |
| 06~10 | 수동 코디 슬롯, 스타일 출처/참고/삭제, 실제 Celery Mock VTON, 별도 실제 착용, 실제 카드 렌더·공유 이미지 HTTP 200 및 폐기 후 404·재사용 |
| 11~14 | 월별 캘린더·착용 취소, 케어 프로필/일정/완료 취소, 보관 분석/승인/실제 이동 확인, 모바일 가로 넘침 없음·Escape |
| 15~18 | 주입한 503/401/409/429, 가족 데이터 격리, 입력 보존, 주입한 27개 페이지 응답의 offset/마지막 버튼, 뒤로가기·새로고침 인증 폐기 |

오류와 pagination 일부는 명시적 브라우저 응답 주입이다. 이를 서버 자체의 장애 복구·동시성 검증으로 주장하지 않는다. 서버 측 근거는 [Sprint 7 검증](SPRINT_7_REPORT.md)의 기존 217개 테스트다. 이번에 backend 로직과 원본 계약은 변경하지 않았다. 자동 검증은 기능 동작 확인이며 화면 만족도·접근성 인증·실 VTON 품질을 보증하지 않는다. 독립적인 사용자 직접 QA가 다음 인수 단계다.

[브라우저 결과](../test-results/frontend-browser-evidence.json), [실행 로그](../test-results/frontend-browser.log), [격리 환경·정리 증적](../test-results/frontend-live-evidence.json), [단위 로그](../test-results/frontend-unit-final.log), [패키지 감사](../test-results/frontend-audit-deps.log), [최종 대조](../test-results/frontend-final-evidence.json)를 따른다. 빌드·포맷·단위·브라우저 명령 및 반환 코드는 test-results의 해당 JSON에 기록한다. npm 감사는 실행 시점 알려진 취약점 0이며 전체 서비스의 운영 안전성 승인은 아니다.

최종 대조에서 HTTP로 제공한 HTML·JS·CSS가 디스크의 빌드와 일치하고, 프론트의 /health/ready 중계가 DB·Redis·Storage·Renderer 모두 정상임을 확인했다. 서버는 127.0.0.1:5173에서 실행 중이며 외부 주소로 바인딩하지 않았다. 원본 계약 7개와 기존 Sprint 7 소스 129개, renderer 소스의 SHA256이 그대로다. 주 DB의 기존 회원 2명·의류 3개·테이블 32개/ENUM 10개·head 0003과 업무 데이터 수를 유지했고 private bucket의 객체는 0개다. 주 DB에 검증 사진이나 업무 기록을 남기지 않았다. 변경 전 기존 217개 백엔드 결과는 과거 증적이며 이번 작업에서 재실행한 것으로 표시하지 않는다.

## 변경 파일과 결정

web/의 React/Vite 소스·CSS·클라이언트·테스트·정확한 버전 package.json/package-lock.json을 추가했다. scripts/verify_frontend.py는 전용 DB/컨테이너·브라우저 검증과 정리를 제공한다. scripts/start_frontend.ps1과 stop_frontend.ps1은 숨겨진 loopback 빌드 미리보기의 기동·종료를 제공한다. 프론트 설계·QA·이 보고서와 README·현재 추적 문서를 갱신하고 node_modules를 gitignore/Docker 빌드 제외에 추가했다. backend 소스·원본 설계 7개·기존 migration·Seed·Compose·.env·시스템 권한/보안 설정은 변경하지 않았다.

OpenAPI 1.7의 공개 경로와 상태·버전을 그대로 사용한다. 위치 목록 API가 없으므로 기존 데모 Seed의 두 위치 이름을 명시적 데모 라벨로 제공하며, 다른 목적지는 이름 미제공으로 표시하고 식별자를 별도로 확인한다. 프로필 선택도 기존 Seed의 로컬 데모 두 회원이며 운영 회원 조회·가입을 구현한 것으로 표시하지 않는다. 입력/표시 시각은 브라우저 현지 시각을 사용하며 API에는 UTC offset 포함 시각을 보낸다. 홈 집계는 서버의 설정 시간대와 출처를 따른다.

발견한 구현 결함은 JSX 괄호 오류, home 배열 필드명 불일치, select label의 옵션 텍스트 혼입, 분 단위 기본 케어 완료 시각이 생성 시각보다 앞서는 문제다. 원본 API를 수정하지 않고 프론트에서 바로잡았다. 새 Chromium은 사용자 캐시에 설치했고 패키지·브라우저 설치를 권한/보안 설정 변경으로 우회하지 않았다.

## 직접 QA와 남은 경계

[직접 QA 절차](FRONTEND_QA.md)를 따라 http://127.0.0.1:5173 에서 `나의 옷장` 프로필로 시작한다. QA의 변경은 로컬 주 DB에 실제 반영된다. 마이의 사진 동의 설정 후 의류 사진과 인물 사진을 등록하면 Mock 입어보기를 실행할 수 있다. 사진 없는 Seed는 미연동/빈 상태를 확인하는 출발 데이터로 유지하며 주 DB에 테스트 사진을 몰래 넣지 않았다.

사용자 QA가 끝날 때까지 미확정 날씨·캘린더·ThinQ·실센서·n8n과 유료 실제 API 테스트는 진행하지 않는다. 실제 Decart 어댑터는 여전히 미구현이며 후속 구현 후 마지막에 유료 호출을 검증한다. 기존 MinIO는 로컬 개발 전용이며 알려진 보안 위험을 해결한 것으로 표시하지 않는다. 이 환경은 인터넷 공개 배포 대상이 아니다.

품질 검토는 재현 가능한 기능 테스트와 실제 저장소·작업 결과를 대조하고, 계약과 현재 문서의 상태 일치를 점검한다. 같은 작성자의 자동 테스트를 사용자 만족도나 외부 품질 평가로 확장하지 않았다. 원본 문서의 과거 프론트 제외는 당시 Sprint 범위로 보존하며 현재 상태는 이 보고서와 README를 따른다. 사용자 QA 결과는 아직 없다.

별도 문맥의 문서 검토에서 발견한 기동 완료 여부·이미 준비된 환경 전제·서버 종료·코디 보관 의미·직접 QA 승인 기준의 누락을 보고서와 QA 문서에 반영했다. 새로운 외부 서비스 품질이나 이식성 주장은 하지 않았으며, 현재 문서 정리 외의 출처 통합은 수행하지 않았다.
