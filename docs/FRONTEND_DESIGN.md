# Smart Wardrobe 프론트엔드 설계

요청 해석: 기존 백엔드 계약 1.7과 FSD의 여섯 IA 메뉴를 실제 화면으로 완성하고 로컬 QA 환경을 제공한다. 사용자 QA 전 미확정 외부 연동이나 유료 API 호출은 수행하지 않는다.

## 화면과 흐름

홈, 옷장, 코디, 캘린더, 케어, 마이를 상위 메뉴로 유지한다. 보관 최적화는 홈/케어에서 진입한다. 공통 입어보기와 코디카드는 상세 흐름으로 제공한다. 데스크톱에서는 고정 좌측 내비게이션, 모바일에서는 하단 메뉴를 사용한다. 밝은 크림 배경과 잉크색 본문, 오렌지 강조색으로 조작과 상태를 구분한다. 외부 폰트나 이미지 요청은 하지 않는다. 실제 이미지가 없으면 의류 실루엣과 이미지 없음 표시를 사용한다.

| 화면 | 기능 | 계약 |
|---|---|---|
| 프로필 선택 | 로컬 데모 세션, 잠금, 만료 처리 | COM-001 |
| 홈 | Context 출처·추천 이유·부분 집계, 추천 실행, 케어/보관 알림 | COM-002, REC-001~002 |
| 옷장 | 필터·페이지, 등록·편집·삭제·공유, 이미지 업로드, 위치, 명시적 Mock 관측, 관리 가이드 | GAR-001~004, STO-001, CARE-001 |
| 코디 | 목록·수동 슬롯 편집·보관, 스타일 출처별 목록·등록·삭제·참고 제작 | OUTFIT-001~002, STYLE-001 |
| 공통 입어보기 | 초기 구성, 인물 업로드, 의류 교체, Mock 비동기 작업·취소·결과·최종 선택 | VTON-001~004 |

| 보관 상세 | 분석 작업·근거·제약, 승인/거절/취소, 개별 실제 이동/실패 확인 | STO-002~004 |
| 마이 | 시간대·단위·알림·사진 동의와 동의 이력, 미연동 상태 | SET-001 |

## 상태·권한·자산

React 상태로 인증을 보관하며 브라우저 영구 저장에 JWT·서명 URL·사진을 저장하지 않는다. 새로고침하면 프로필 선택으로 돌아간다. 잠금/401에서 사용자 데이터와 진행 중 화면을 폐기한다. 변경 버튼은 실행 중 중복 클릭을 막는다. 네트워크 오류의 동일 요청 재시도에는 동일 Idempotency-Key를 사용한다. 409는 새로고침 안내를 제공하며 version/revision을 우회하지 않는다.

목록은 실제 API pagination을 따른다. 로딩·빈 상태·실패·부분 실패를 구분한다. 작업은 실제 Job polling과 terminal 상태를 표시하며 성공을 추정하지 않는다. 입어보기 종료·카드 저장·착용 확인·보관 승인·실제 이동을 각각 별도 조작으로 제공한다. 의류 접근 권한은 서버가 판정하며 다른 프로필로 전환 시 로컬 상태를 초기화한다.

사진은 동의 확인 → upload intent → 서명 PUT → SHA256 finalize → 도메인 연결 순서다. 개발 프록시는 고정 loopback MinIO의 wardrobe-assets 경로만 중계한다. 임의 URL 중계와 외부 이미지 크롤링은 없다. 이미지 실패는 다시 조회 안내와 placeholder를 제공한다. 스타일 외부 링크는 HTTP(S)만 허용하고 새 창에서 noopener/noreferrer로 연다.

Mock VTON은 실제 합성 결과가 아님을 표시한다. 센서 관측은 명시적 Mock 입력만 제공한다. Decart·LIVE 날씨/캘린더·ThinQ·실센서 연결을 성공으로 표시하지 않는다. 비용 발생 요청은 구현하지 않는다.

## 로컬 실행과 검증

web/의 React/Vite 패키지는 정확한 버전과 lockfile로 고정한다. 개발/빌드 미리보기 모두 127.0.0.1:5173만 사용하며 기존 API를 같은 origin의 /api로 중계한다. backend·원본 설계 7개·Compose·보안 설정은 변경하지 않는다. Vite proxy 설정은 [공식 문서](https://vite.dev/config/server-options)의 server.proxy와 preview 설정을 따른다.

검증은 API 클라이언트의 오류/키 재사용/자산 URL 규칙 테스트, 빌드·패키지 감사, 실제 Chromium과 격리 API/DB/Celery/MinIO의 사용자 흐름 테스트로 수행한다. 모바일 화면·키보드 dialog·오류/빈 상태도 확인한다. 개발자 검증 완료와 사용자 직접 QA 승인은 별도로 기록한다. QA 이후 선택 연동과 마지막 유료 VTON 검증을 진행한다.
