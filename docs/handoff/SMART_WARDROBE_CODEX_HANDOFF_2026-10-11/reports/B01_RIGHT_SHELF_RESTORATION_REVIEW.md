# B-01 오른쪽 선반 복원 검토

2026-10-12 · 조사 기준 `b0dde4e` · 분석 전용, 구현 승인 전

이 지시는 오른쪽 선반의 표시 문제를 원본·DB 매핑·실제 렌더링으로 분석하고 복원안을 제안하는 것으로 이해했다. 왼쪽 행거, 기존 데이터, 다른 B 잔여 항목 및 C~G는 수정하지 않았다. SQL은 SELECT만 사용했다. 브라우저에서는 기존 시연 로그인과 화면 조회만 실행했다. 결과 문서와 조사 증적만 새로 작성했다.

## 1. 확인 근거와 현재 구조

- 기존 판정: [STAGE_B_IMPLEMENTATION_REPORT](STAGE_B_IMPLEMENTATION_REPORT.md). B는 여전히 PARTIAL이다.
- 형태·배치 기준: [원본 앱 화면](../references/wardrobe/wardrobe_ui_original.png), [원본 이미지](../../../../web/public/assets/mirror-final/wardrobe-reference.png). 전자는 브라우저 상단·작업표시줄을 포함하므로 전체 캡처를 바로 겹치면 안 된다. 후자는 앱과 같은 1672×941 기준이다. 원본 조명점의 재도입은 이번 범위가 아니다.
- [이번 실제 브라우저 캡처](evidence/b01/browser-current.png): 1672×941, DPR1, 최휘재 로그인 완료·이미지 decode 후 촬영. 오른쪽 66벌을 실제 Scene 응답과 DOM에서 확인했다. 전체 기능 정상 판정은 하지 않았다.
- `backend/app/application/wardrobe_scene.py`: `scene_placement` → 물리 칸 → geometry, 원본 asset metadata의 `scene_sprites.folded` → 파생 asset/mask → Scene 응답.
- `web/src/mirror/source/WardrobeSceneLayers.tsx`: garment_id별 SVG와 클릭 영역. `maskViewBox()`의 crop을 사용하고 선반은 `xMidYMax meet`로 비율 유지·하단 정렬한다.
- `web/src/mirror/source/sceneImageGeometry.js`: 유효 crop을 그대로 반환한다. 이번 조회에서는 마스크 외부의 큰 아틀라스 여백을 그대로 표시하는 오류가 아니었다.
- `scripts/stage_b_seed.py`: 11칸, 칸마다 좌우3벌. 모든 상자가 108×22px, 층간 간격22px, 최하단은 바닥 기준5px 위. 내측 칸의 상자 간 좌우 간격25px, 외측72px이다.

**66벌은 66개의 독립 이미지 파일이 아니다.** 35벌은 기존 아틀라스5장의 서로 다른35개 crop에 연결되어 있고, 31벌은 승인 K1~K3의 독립 측면 PNG3종을 11/10/10회 재사용한다. 고유 garment_id와 공유 asset은 별개다. 이번 DB 조회에서 이 매핑을 확인했으며 신규 상품이나 의류를 추가하지 않았다.

수치 및 의류별 매핑은 [asset-measurements.json](evidence/b01/asset-measurements.json)에 기록했다. 표시 폭 수치는 crop과 SVG meet 규칙으로 계산한 값이며 실제 불투명 픽셀 외곽을 직접 측정한 값과는 구분한다.

비율 유지 자체는 정상이다. CSS로 가로만 늘려 문제를 숨기면 소재·로고·주름이 찌그러진다. 기존 보고서의 ‘여백’ 설명을 이번 조회에서는 **상자와 에셋의 비율 불일치 및 개별 실루엣 여백**으로 구체화했다. 과거 아틀라스 metadata도 `local_display_candidate_not_product_fidelity_certified`이며 상품 충실도가 인증된 상태가 아니다.

또한 현재 Scene의 `quality_status=approved`는 승인된 clean plate 존재 여부만 본다. geometry의 `approved=true` 역시 좌표 유효성 검사 조건이지 원본 시각 합격 증거가 아니다. 두 플래그를 B-01 시각 완료 판정에 사용하면 안 된다.

## 3. 원본 재사용 범위

재사용: 칸 경계, 카메라 원근, 나무 배경·선반 앞판, 바닥 접점, 묶음 폭·총높이·간격, 소재별 측면 형태의 참고, 기존 clean plate 및 승인 K1~K3 파생 에셋.

제한: 원본에 그려진 옷은 현재35개 상품의 실제 파생 에셋으로 간주할 수 없다. 원본 묶음 통이미지를 깔고 보이지 않는 클릭 ID66개를 얹으면 ID가 화면의 실제 의류와 대응하지 않고 이동·숨김·개별 조명에 실패한다. 원본 옷 픽셀을 그대로 재사용하려면 해당 시각을 상품별 표현으로 사용해도 되는지 별도 승인이 필요하다. 이번 권장안은 그렇게 처리하지 않는다.

## 5. 승인 후의 구현 방식과 예상 수정 범위

1. 기존66개 garment·칸·상품 매핑 고정. 원본의22묶음 외곽과11개 바닥 접점을 먼저 좌표로 기록한다. 개별 좌표는 렌더링 파생값이며 DB의 보관 위치는 계속 칸 단위다.
2. 기존35벌에 대해 상품의 색상·소재·무늬를 참고한 낮고 넓은 측면 파생 에셋을 확보한다. 원본 상품 사진은 유지한다. 같은 상품의 복수 인스턴스는 파생 이미지 재사용 가능하되 서로 다른 상품을 임의로 같은 그림에 매핑하지 않는다.
3. 파생 에셋마다 불투명 외곽, 하단 접점, 적층 접점, 그림자 범위를 정의한다. K1~K3도 접점을 측정한다. 고정22px 대신 아래 옷 윗접점에 다음 옷 밑접점이 닿도록 쌓고, 묶음 폭·총높이·간격을 원본 기준으로 맞춘다.
4. geometry는 Scene의 기존 개별 item으로 공급한다. SVG clip/mask, 캐시, 의류 선택·숨김 경로를 유지한다. 필요한 shadow는 개별 에셋/레이어 안에서 제한하고 직사각형 배경을 넣지 않는다.
5. 같은 칸6개의 개별 표시와 칸 LED 공유를 다시 검사한다. 기존 장치 동작이나 LED 정책은 변경하지 않는다.

## 6. 시각 완료 기준 제안

아래 수치는 **승인받을 검증안**이며 기존 계약에 이미 확정된 숫자가 아니다. 먼저 원본에 수동 추적한 기준을 동결해야 한다. geometry를 만든 코드가 만든 좌표를 그대로 정답으로 검사하지 않는다.

동일 조건: 원본1672×941, 브라우저 viewport1672×941·DPR1·zoom100%, 동일 옷장 컨테이너 위치/크기, 이미지 모두 decode, 조명 비선택 기본 상태. 비교 영역은 오른쪽 E1~E4/F1~F7만 사용한다. 원본의 중앙·행거·브라우저 장식·발광점은 점수에 넣지 않는다.

추적 기준은 각 묶음의 불투명 옷 외곽으로 하고 바닥선은 실제 옷이 얹히는 선반 윗면으로 한다. 측면 방향도 각 묶음의 원본 참조와 짝지어 기록한다. 이 기준표는 아직 작성·승인되지 않았으므로 현재 숫자는 검증안이지 완료 판정 결과가 아니다.

| 검증 요소 | 제안 합격 기준 | 증적 |
|---|---|---|
| 형태 | 66개가 측면 접힘으로 읽힘. 앞판·목둘레 중심의 정면 셀0개, 직사각형 배경0개. 상품 색상·소재 대응은 별도 사람 검수 | 원본/실제 칸별 확대 비교, 파생 셀 목록 |
| 수량과 독립성 | 11칸 모두 좌우2묶음×각3벌, 고유ID66. 각ID 숨김 시 정확히 해당1벌만 사라짐 | API/DOM·개별 숨김 확인. UI 신규 버튼은 만들지 않음 |
| 크기 | 원본에서 추적한 각 묶음의 불투명 외곽 폭·총높이 대비 편차 각10% 이내. 원근·소재 차이를 유지, 비균등 stretch 금지 | 22묶음 실루엣 bbox와 원본 측정표 |
| 간격·접점 | 좌우 묶음 간격은 원본 추적값 대비±5px. 상하 적층 접점의 빈 공간0~2px, 의도된 겹침0~3px. 최하단 실루엣/접촉 그림자는 바닥 접점에서0~2px, 앞판 침범0px | 100% 및 확대 이미지, 바닥선 표시된 비교 증적 |
| 밀도 | 각 칸의 좌우 묶음 폭 합/칸 폭, 묶음 총높이/칸 높이를 원본 대비±10% 이내로 맞춤. 그림자·투명 여백 제외 | 칸별 비율22묶음 측정 |
| 원근·빛 | 원본과 같은 측면 방향, 일관된 광원, 바닥 접촉 그림자. 선택·개별 숨김 때 주변 옷/배경을 함께 자르지 않음 | 기본/레이어 확인 이미지 + 사용자 시각 승인 |
| 보존 | 해당66개 ID·상품·칸·소유 관계 유지. 이번 B-01로 왼쪽 이미지/geometry/동작 변경0, 기존 데이터 삭제0 | 전후 범위 diff·참조 검사 |

전체 이미지 픽셀 일치나 SSIM 점수는 상품 교체와 빛 차이 때문에 단독 합격 기준으로 사용하지 않는다. 숫자 검사를 통과해도 형태·상품 충실도·자연스러움에 대한 사용자 시각 승인이 없으면 시각 Gate를 통과시키지 않는다.

## 7. 위험과 결정 사항

- 생성/수작업 측면 에셋은 실제 상품의 보이지 않는 접힘·두께를 추정한다. 원본 사진은 그대로 유지하고 옷장 표시용 파생임을 구분해야 한다. 기존 아틀라스의 상품 충실도 미인증 상태도 새 검수에서 확인해야 한다.
- 31개 인스턴스가3종을 반복하므로 색·소재 반복은 남는다. 현재 데이터를 유지하는 이번 권장안에서는 임의의 색상 변경이나 신규 상품 추가를 하지 않는다.
- 원본 비율을 맞춰도 에셋 자체의 그림자 방향·외곽 여백이 다르면 다시 떠 보일 수 있다. 접점과 그림자를 포함해 검사해야 한다.
- 사용자가 결정할 사항: **C+D 권장안 채택**, **35벌용 파생 제작 방법·비용 허용 범위**, **위 시각 기준의 허용 오차 승인**. 유료 생성 호출은 별도 승인 전 실행하지 않는다.
- 원본 옷 픽셀을 다른 상품에 그대로 붙이는 저비용 우회안은 권장하지 않는다. 별도 승인 없이 채택하지 않는다.

현재는 분석만 완료했다. B는 PARTIAL을 유지하며 구현·DB 변경·에셋 변경·원격 push·배포 및 다른 단계는 실행하지 않았다.

독립 검토(`sip`/`shower`)에서는 승인 전 제안임을 확인했고, 측정 경계·묶음별 방향·B 전체 상태의 구분을 보완했다. `mandela` 기준으로 구현 좌표를 검증 정답으로 쓰는 순환을 피하도록 원본 추적본을 별도로 동결하는 Gate를 유지했다. 기존 계약·B 보고서와의 정합성은 `ssotize` 읽기 전용으로 확인했으며 원문은 수정하지 않았다. 외부 제품·서비스 사실이나 이식성 주장이 없어 외부 `factchk` 조회와 `detool`은 적용하지 않았다. `re0`로 검증안과 실제 확인 결과를 구분했다. 독립 검토 범위는 권장안·시각 검증 기준이며 브라우저의 시각 합격 판정을 대신하지 않는다.

B-01 시각 승인을 받아도 일반 위치 API 정합성은 별도 B 잔여 항목이다. 이번에는 그 항목을 조사·수정하지 않았고, B 전체 완료는 두 잔여 항목 검증을 모두 충족할 때만 갱신한다.
