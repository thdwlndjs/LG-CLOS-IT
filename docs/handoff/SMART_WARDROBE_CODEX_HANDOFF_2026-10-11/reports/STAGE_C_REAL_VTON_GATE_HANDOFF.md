# 실제 시착 시연 별도 게이트 인계

C1~C6의 Mock PASS는 실제 시착 품질 PASS가 아니다. 최종 PoC에서 실제 착장을 보여주는 시연은 이 게이트를 별도로 통과해야 한다. 현재 유료 공급자 호출 및 실제 시착 품질 검증은 수행하지 않았다.

## 현재 연결 가능한 계약

- C는 보유/LIKED/혼합 품목을 `kind + id`로 구분하고, 원본 asset ID·SHA256·출처·슬롯을 요청 시점 Snapshot에 고정한다.
- 인물 사진 1장과 선택 의류 전체의 실제 이미지 바이트를 검증한다. 요청 Job과 마지막 표시 결과의 Snapshot은 현재 편집 중인 조합과 독립적이다.
- C Mock 출력은 `MOCK_RECEIPT_NOT_REAL_TRY_ON` 처리 확인 이미지다. 실제 의류 착장·인물 합성·체형·재질·무늬·레이어 순서 재현을 하지 않는다.
- 기존 서버 `DecartAdapter`는 `PROVIDER_CAPABILITY_UNAVAILABLE`을 반환한다. 프론트 SDK 경로의 존재만으로 서버의 다중 의류 입력이나 실착 품질이 검증된 것은 아니다.
- C 통합 경로는 private local/test의 MOCK에 제한한다. 설정 변경만으로 이 경로가 유료 공급자를 호출하지 않는다.

## 실제 시착 시연의 의존성과 검증

| 게이트 | 필요한 작업과 증적 | 현재 상태 |
|---|---|---|
| 별도 실행 승인 | 공급자·허용 비용·실제 호출 범위·인물 사진 사용 동의 확정 | 미승인 |
| 입력 수용 계약 | 6개 슬롯, 슬롯당 1개, TOP+BOTTOM 또는 DRESS, 보유/LIKED/혼합의 입력 방식·지원 수량 확인 | 미검증 |
| 공급자 어댑터 | 실제 공급자가 지원하는 입력에 맞춘 전송·인증·상태 조회·취소·타임아웃·실패 처리. 지원하지 않는 조합을 명시적으로 차단 | 미구현/미검증 |
| 실착 품질 | 인물 동일성, 선택 의류 일치, 색·무늬·재질, 앞뒤/각도, 체형, 상하의·아우터 겹침, 신발/액세서리 표현의 실제 결과 검수 | 미검증 |
| Snapshot 계승 | 실제 공급자 요청과 결과가 C Snapshot에 대응하는지 검증. 생성 중 편집·이탈·프로필 전환·중복 요청·오류 복구 재검증 | Mock 흐름만 검증 |
| 데이터 및 권한 | 본인 인물 사진, 가족 공유 보유 의류, 본인 LIKED, 사진 소유자 동의·보관 기한·삭제 정책의 실제 외부 전송 검사 | 로컬 Mock만 검증 |
| 비용 및 제한 | 호출 건수·비용·재시도 상한·공급자 할당량·원격 보관/삭제·장애 시 사용자 안내 확인 | 미검증 |
| D/F 연결 | 서버가 Job의 결과 Snapshot을 재조회하여 착용 확정/LED 및 코디카드 대상을 결정. LIKED 결과 제한과 결과 미표시 대체 금지 검사 | D/F 미승인 |

슬롯 종류는 6개지만 DRESS와 TOP/BOTTOM의 상호 배타 조건 때문에 현재 정책의 유효 조합은 최대 5개다. 이 사실을 공급자 수용 계약에서도 구분한다. Mock는 공급자마다 다른 실제 입력 한계의 증거가 아니다.

## 다음 작업의 인계 기준

실제 공급자 연동은 C 완료 보고 이후 별도 승인에 따라 진행한다. D/F는 표시된 Job ID로 서버 Snapshot을 재조회하고 권한·동의·입력 변경 여부를 검증해야 한다. 프론트에 표시된 Snapshot이나 `contains_liked` 값을 서버 실행 권한으로 신뢰하지 않는다. B-02 위치 정합성은 계속 DEFERRED이며 실제 위치·실물 LED 정확도를 보증하지 않는다.

현재 draft 편집은 허용되며 결과 Snapshot의 유효성을 바꾸지 않는다. 여기서 입력 변경 검사는 DB의 원본 이미지 ID·checksum·garment 버전·접근 권한·동의가 요청 이후 달라졌는지를 뜻한다. 원본이 변경됐다면 기존 이미지를 새로운 원본인 것처럼 재사용하지 않고 입력 재확인·재생성을 요구한다.

승인자는 사용자이며 다음 게이트의 실행 계약과 명시적인 사용자 지시를 증적으로 남긴다. 공급자 선택, 품질 검수자·PASS 기준·미지원 슬롯 처리 정책은 아직 확정하지 않았다. 6개 슬롯 지원 정책은 목표이고, 현재 유효 최대 5개 조합은 선택 제약에서 나온 상한이지 공급자가 이미 수용했다는 의미가 아니다. 실착 품질과 지원 범위가 부족하면 결과를 PASS로 바꾸지 않고 사용자에게 제한 및 후속 결정을 보고한다.

구현 진입점은 `backend/app/application/poc_vton.py`, `poc_vton_worker.py`, `domain/vton.py`, `web/src/mirror/source/pocVton.ts`다. 검증 증적과 로컬 재현은 [C 완료 보고](STAGE_C_IMPLEMENTATION_REPORT.md) 및 [stage-c 증적](evidence/stage-c/)을 참조한다. 이 문서는 남은 게이트를 인계하며 실제 공급자 연동을 승인하거나 비용을 확정하지 않는다.
