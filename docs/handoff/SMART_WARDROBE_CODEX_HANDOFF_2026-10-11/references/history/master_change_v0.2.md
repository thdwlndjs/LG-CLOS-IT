## A. 계약 우선순위 및 변경 관리

1. 기존 운영 코드·DB·API 계약을 먼저 읽고 현황표 작성. 기존 계약과 본 변경안이 충돌하는 부분은 **명시적 변경 대상**으로 분류한다.
2. 사용자 승인된 UX 변경 요구사항은 새 목표 상태로 유지하되, 실제 API/DB 필드·엔드포인트·경로는 현행 저장소에 매핑한다. 근거 없이 테이블·라우트를 발명하지 않는다.
3. 구현이 미완료인 항목은 `planned`로, Mock은 `mock`으로, 실기기 연동은 검증 시에만 `verified`로 표기한다.
4. 기존 기능 보존, 변경 범위 최소화, 각 단계별 테스트·회귀 QA. 미해결 외부 API 지원 범위는 차단 이슈로 보고한다.
5. 원격 `main` 백업/푸시 → `dev` 작업 브랜치 생성 → 단계별 커밋 → 사용자 QA 승인 후에만 `main` 반영. 원격 푸시·병합 전에는 실제 상태·권한을 확인한다.

## B-0. CHG-00 — DB 적재·시드·상태 동기화 계약 (신규, 필수 선행)

**원칙:** 현행 DB/API 스키마를 먼저 감사한 뒤 논리 필드를 기존 테이블에 매핑한다. 본 목록은 신규 테이블 생성 명령이 아니다. 시연 데이터는 실제 에셋과 정합성을 검증한 뒤 적재한다.

### 필수 시드 데이터 계약

1. **옷장 내부 21벌:** 롱 아우터 7, 숏 아우터·상의 6, 바지 8. 각각 실제 등록 `garment_id`·이미지·구획·슬롯에 1:1 대응. 이는 전체 가구 의류 수량이 아님.
2. **외부 보관 의류:** 계절 전환 시연을 위한 실제 등록 의류를 별도 수량으로 확정. 옷장 21벌과 중복 계수 금지. 기존 18벌 예시 데이터는 승인 전 그대로 삽입하지 않음.
3. **보관 공간:** 옷장 및 최소 두 외부 공간을 시연 후보로 구성하되 실제 공간 구조·수용량·HA 제어 능력은 검증 전 가정값으로 표시.
4. **환경 시연값(초안):** 옷장 22°C/58%, 첫 번째 방 23°C/72%, 두 번째 방 20°C/45%. `is_demo=true`, `source=mock` 필수. 습도 40–55%, 온도 ≤25°C는 시연용 규칙이지 소재별 보편적 보관 기준이 아님.
5. **추천 재현 데이터:** 날짜가 명시된 날씨 예보·일정·착용 이력·이동 이력과 추천 입력 스냅샷을 적재. 코디 추천 2–3개는 실제 이미지 보유 의류만 사용.
6. **상태 이벤트:** 추천 생성 → 사용자 수락 → 이동/제어 요청 → 실제 완료 확인 → 위치/환경 갱신. 과거 이력과 현재 상태가 불일치하면 적재 실패.
7. **시드 재실행:** idempotent/upsert 또는 테스트 전용 초기화 절차, 재실행 시 중복 방지, 실제 운영 데이터 보호, 테스트 롤백/백업.

### 데이터 QA 게이트

- 전체 의류 수 = 옷장 21벌 + 외부 공간 등록 의류 수 + 기타 위치 의류 수; 모든 의류 위치·소유자·이미지 참조 유효.
- DB 현재 위치 = 화면 표시 슬롯 = 검색 결과 = 조명 매핑. 이동 완료 시 네 곳 동시 정합성 확인.
- 추천 근거에 참조된 환경/날씨/이력 레코드가 실제 존재하며 시각과 출처를 확인할 수 있음.
- 승인 전 위치 미변경, 실패한 HA 명령의 성공 처리 금지, 실제 착용 기록 자동 생성 금지.
- 카드 생성은 등록 의류만, 템플릿/이미지 버전 및 결과 에셋을 추적.

**미결정:** 전체 의류 수·실제 이미지 확보·슬롯 물리 좌표·수납 단위·데모 날짜·센서 최신성/환경 제어 정책·현재 스키마 매핑. Codex 감사 단계에서 확인하고 사용자 승인 전 임의 확정 금지.



### CHG-01 — AI 입어보기 진입점/IA
- `미러로 비교`, `미러로 입어보기` 같은 중복 진입 명칭은 **`AI 입어보기`**로 정리한다. 화면 제목과 진입 CTA의 최종 카피는 사용자 승인값을 우선한다.
- 홈 `오늘의 코디 추천`: 보유 의류 기반 2–3개 코디를 **가로 캐러셀**로 제공. 별도 `추천 코디 비교하기` 메뉴·비교 화면은 **삭제**한다.
- 홈·내 코디·코디 만들기/편집·옷 상세·캘린더 과거 코디에서 선택 의류 조합을 공통 AI 입어보기로 전달. 해당 화면에 실제 진입점이 없는 경우 신규 노출은 현행 IA와 대조 후 결정.
- 피팅 종료·취소·뒤로 가기 시 원래 화면의 코디 선택/편집 상태 및 홈 캐러셀 위치 보존.
- 진입과 VTON 실행은 별도 상태. `idle → preparing → running → succeeded | failed | cancelled`. 화면에 별도 ‘미러 비교’ 중간 단계를 추가하지 않는다.

### CHG-02 — VTON 두 실행 방식
- **실시간 카메라 기반**: 카메라 권한 → Decart의 공식 지원 API 확인 → 세션/영상 처리 → 결과 출력/종료.
- **사진 기반**: 인물 사진 및 동의 → 공식 지원 정적 VTON 경로 확인 → 작업 생성/상태 조회 → 결과 표시.
- Decart의 실제 제공 범위(실시간 영상·정적 이미지·상의/하의 동시 입력·의류 이미지 포맷·요금·세션 제약)는 **구현 전 검증 필수**. 미지원 기능을 ‘실제 연동’이라고 표시하거나 임의 우회 구현하지 않는다.
- 비밀키는 서버/환경변수에만 두고 클라이언트·로그·문서에 노출하지 않는다. 사진·동의·결과물의 보관/삭제 정책은 기존 계약에 매핑한다.
- VTON 실패·취소 시에도 코디 확정과 코디카드 제작은 독립 실행 가능.

### CHG-04 — 코디카드 진입점 및 생성
- 코디카드는 **추천 시 자동 생성하지 않는다**. 사용자가 명시적으로 요청해야 한다.
- 진입: 코디 만들기/편집, 내 코디, 홈에서 코디 선택 후, AI 입어보기 화면, ‘이 코디 입기’ 직전, 과거 코디 재사용. 보유 의류만 카드에 사용.
- 카드 제작은 VTON 결과 사진을 자동 합성하는 기능이 아니다. DB의 개별 의류 이미지 → 4종 템플릿 → PNG → 저장/공유.
- `코디 확정`, `착용 예정`, `실제 착용`, `코디카드 생성`은 별도 이벤트. 카드 생성/확정이 실제 착용 이력을 자동으로 만들지 않는다.

### SW-CARD-TEMPLATE-001 — 4종 템플릿 복원 품질 계약
- T1–T4는 서로 다른 원본 구도·접힘·레이어·가림·광원·그림자를 갖는 **독립 템플릿**. 공통 템플릿 하나로 평균화 금지.
- 원본 레퍼런스 4장과 Markdown 계약을 기준으로 **픽셀/마스크/좌표/변환행렬/레이어 순서** 추출. 텍스트·하단 어두운 오버레이 제거, 원본에 없는 가려진 픽셀은 무손실 복원 주장 금지.
- 권장 파이프라인: 원본/마스크 분리 → JSON/SVG/RGBA 에셋 → React 렌더 → Playwright PNG.
- 신규 의류 리타깃팅은 원본 템플릿 복원과 별도 난이도. 형태·로고·색상·패턴을 훼손하면 무변형 컷아웃 또는 수동 검수로 폴백.
- Gate A: 템플릿별 원본 재구성 검증. Gate B: 등록 의류 치환 품질 검증. Gate C: 배포 환경 E2E PNG 생성·저장·조회 검증. 지표 합격선은 기준 이미지 확보 후 설정.
- 이미지 저장은 기존 `image_asset_id`/`asset_key`/서명 URL 계약 준수. 만료 `read_url` 영속 저장 금지. 실제 스키마는 대조 후 확정.
- SNS 자동 게시, 범용 의류 접힘 생성 모델은 범위 밖.

### CHG-08 — 옷장 DB 연동 시각화·조명
- 시연용 수납 목표 **총 21벌**: 롱 아우터 7, 숏 아우터·상의 6, 바지 8. 구획 A/B/C와 슬롯은 **임시 논리 구조**이며 실제 옷장 이미지/물리 구획과 대조해 확정.
- 고정 배경 이미지에 의류가 이미 그려진 경우 이를 제거/교체. 프레임 레이어 + DB 의류 이미지 레이어 + 조명 레이어로 동적 렌더링.
- 위치 매핑 논리: `garment_id → space_id → compartment_id → slot_index → light_zone_id`. 좌표·크기·z-index는 실제 렌더 레이아웃에 별도 매핑.
- `내 옷 찾기`는 대상 의류 위치 강조/점등, `이 코디 입기`는 선택 코디 의류가 속한 모든 **서로 다른 조명 구역** 점등. 구획 LED는 해당 구획 전체가 켜지므로 의류 개별 강조는 화면 오버레이로 보완.
- 자동 소등, 위치 미확인, 미연결 공간, 제어 실패, 중복 명령을 처리. Mock LED와 실제 하드웨어 실행 결과 구별.
- 옷장 외 보관함은 공간 디지털 모델로 관리. 외부 의류 이동은 사용자 **일괄 이동 확인**을 기본으로 하고 RFID·비전 자동 추적은 확장 범위.

### CHG-09 (정책·알고리즘 상세 계약 미완성) — 계절·보관 최적화 에이전트
- 옷장 외 방·수납함까지 공간/위치/온습도/용량·제어 가능한 HA 기기를 모델링.
- 예보·계절·착용 이력·의류 소재·공간 환경으로 이동/회수/환경 제어를 **선제안**.
- 제안 → 사용자 승인 → 실제 이동 확인/제어 결과 → 상태 갱신을 구분. 기기 권한·센서 최신성·수납 용량·소재 제약 확인.
- 데모 환경 측정치/기준은 Mock임을 표기하고 실제 의류별 최적 조건으로 일반화하지 않는다.
- **DB 논리 계약은 CHG-00에 정의했으며, 실제 스키마 매핑·정책·실제 시드 레코드·수용 기준은 미확정**: 이 항목은 현 단계에서 구현 자동 착수 금지, 별도 상세 계약 승인 필요.

## D. 단계별 테스트 시나리오 (최소)

2. 코디 편집에서 의류 변경 → AI 입어보기 → 최신 `garment_id`로 피팅/확정/카드 제작.
3. 사진/실시간 피팅의 권한 거부·실패·취소·성공 각각 분기. Mock 결과를 실제 Decart 결과로 표시하지 않음.
4. VTON 없이 카드 제작 → T1–T4 템플릿별 PNG 생성 → 에셋 조회·다운로드/공유.
5. 등록되지 않은 외부 의류로 카드 생성 시 거절. 생성 시 실제 착용 이력 생성 금지.
6. 옷장 21벌의 DB 위치/화면 배치 일치; 한 벌 이동 시 해당 슬롯만 변경.

8. 외부 보관 의류는 LED 미연결 시 위치 안내만. 이동 제안 승인만으로 위치 변경 금지; 일괄 이동 확인 시 갱신.
9. API/카드 이미지 서명 URL 만료 시 갱신·재시도; 영속 저장에 만료 URL 미기록.
