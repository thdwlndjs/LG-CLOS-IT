## 1. 목적 및 원칙

제공된 **서로 다른 4장의 패션 플랫레이 시안**을 각각 독립적인 조형 템플릿으로 보존하고, 실제 보유 의류의 이미지를 해당 레이어에 치환하여 재현성 높은 코디카드 PNG를 생성한다.

**원칙**
1. 템플릿 T1–T4는 독립적이며, 위치·실루엣·접힘·가림·광원·소품 관계를 공통 템플릿으로 평균화하지 않는다.
2. 이미지 → 자연어 묘사 → 코드의 추측성 재구성을 금지한다. **원본 픽셀, 마스크, 변환행렬, 좌표, 가림 관계**를 구현 데이터로 사용한다.
3. 사진 질감과 복잡한 주름은 래스터 에셋으로 보존한다. SVG는 래스터 이미지를 포함하는 레이어·마스크·좌표 컨테이너로 사용한다.
4. **Figma는 필수 단계가 아니다.** 레이어 추출(SAM 2 등) → 픽셀 보정(GIMP 등) → SVG/JSON → React → Playwright가 기준 경로다.
5. 오픈소스 우선. 이미지 변환에 유료 API 또는 배포 서버의 상시 GPU를 필수 조건으로 두지 않는다.
6. **템플릿 복원**과 **새 의류 사진의 형태 재타깃팅**은 별도 단계·별도 품질 기준이다. 첫 번째 성공이 두 번째 성공을 보장하지 않는다.

## 3. 입력 시안 전처리 계약

### 3.1 기본 출력에서 제외
- 제목·부제·출처·브랜드 등 **시안 위의 모든 타이포그래피**.
- 하단 텍스트 가독성을 위해 추가된 **어두운 그라데이션/오버레이**.
- 타이포·오버레이의 잔상 및 인페인팅 아티팩트.

### 3.2 보존
- 의류의 실제 주름·접힘·소재 질감·광원·물체 간 가림·접촉 그림자.
- 바닥의 타일 질감·광원·공간적 비율(단, 오버레이로 손상된 영역은 복원 후 별도 검증).

### 3.3 불확실성
- 텍스트와 오버레이 아래에 가려진 실제 픽셀은 원본 4장만으로 **무손실 복구 불가**.
- 복원 작업에는 원본 무자막 사진 확보를 최우선으로 하고, 없으면 인페인팅 후 해당 영역을 `reconstructed`로 표기한다.
- '무손실'은 **원본에서 관찰 가능한 픽셀과 좌표의 보존 목표**이지, 존재하지 않는 픽셀의 정확한 복구 보장이 아니다.

## 4. 템플릿 제작 파이프라인 (오프라인, 최초 1회)

1. 원본 해상도·색공간·종횡비 기록, 원본 파일 해시 보존.
2. 텍스트·어두운 오버레이 분리 및 복원; 변경 영역을 마스크로 기록.
3. SAM 2 또는 동등 도구로 의류·소품 인스턴스 분할; 실패한 경계는 GIMP 등으로 수동 정정.
4. 원본 RGBA 픽셀, 알파 마스크, 원본 좌표계 bbox, 가림 순서, 필요 시 부분별 마스크·앵커 추출.
5. 가려진 부위는 억지로 생성하지 않는다. 보이는 레이어와 치환 시 추가로 필요한 영역을 구분한다.
6. 각 템플릿별 JSON + SVG 래퍼 + RGBA 에셋 생성. 원본에서 유래한 마스크·변환값은 재계산하지 않고 보존.
7. 원본 에셋을 그대로 재조합한 React 렌더를 Playwright로 PNG 출력 후 원본과 정합성 비교.
8. 템플릿별 검수 완료 후 버전 고정.

## 5. 데이터 계약

### 5.1 TemplateManifest (템플릿당 1개)
- `schema_version`, `template_id`, `template_version`, `source_reference`, `source_sha256`
- `canvas`: `width_px`, `height_px`, `color_space`, `background_asset`
- `layers[]`: `layer_id`, `role`, `source_asset`, `alpha_mask_asset`, `bbox_px`, `transform_matrix`, `z_index`, `clip_path`, `occlusion_dependencies`, `replaceable`, `asset_requirements`
- `reconstruction_regions[]`: `mask_asset`, `method`, `verified` (복원된 영역 추적)
- `render`: `device_scale_factor`, `font_policy`, `transparency_policy`, `export_format`
- `qa`: 원본 재구성 검증 결과·마스크 보정 상태·승인자·버전

### 5.2 OutfitCardRequest
- `template_id`, `template_version`, `outfit_id`, `member_id`
- `slot_assets`: `layer_id -> garment_id + image_asset_id + (선택) styled_asset_id`
- `context`: 선택된 착용 경험/추천 근거/날씨 등 (본 계약의 기본 무자막 출력에는 표시하지 않음)
- `export`: `png`, 원본 캔버스 해상도 기본값

### 5.3 저장 계약
- 기존 프로젝트의 `image_asset_id`·`asset_key`·서명 URL 계약을 존중한다. 영속 레코드에 만료되는 `read_url`을 저장하지 않는다.
- `styled_asset_id`는 원본 의류 에셋과 별도 버전으로 연결한다. 이미지 변경 시 파생 에셋 캐시를 무효화한다.
- `rendered_card_asset_id`는 생성 카드의 저장 참조다. 실제 테이블·필드 이름은 현행 DB/API 계약과 대조 후 결정한다.

## 6. 신규 의류 치환 (Garment Retargeting) 계약

- 원본 쇼핑몰 이미지 → 배경제거·크롭·색상 보존 → 카테고리별 랜드마크/마스크 정규화 → 템플릿 슬롯별 정합 → 렌더.
- 소매·바짓단 등의 굴곡은 검증된 변형 프리셋에 한해 사용한다. 원본 로고·단추·패턴·색상이 손상되면 해당 변형을 폐기한다.
- **접힘 형태를 정확히 재생성할 수 없으면** `unmodified-cutout`으로 대체하거나 `manual-review-required`로 표시한다. 품질을 가장한 조작이나 허위 동일성 주장을 금지한다.
- 템플릿별 허용 카테고리, 가방 끈·신발 한 켤레 처리, 보이지 않는 면의 합성 정책은 별도 `retargeting-profile`에서 정의한다.
- 단순 이미지 치환만으로 T1–T4의 원래 접힘도가 보존된다고 가정하지 않는다.

## 7. React 렌더링 및 Playwright 계약

- React 템플릿은 T1–T4 각각 독립적인 구도·레이어 정의를 가진다. 공통화는 RGBA 이미지·마스크·좌표 변환·에셋 로더 같은 **렌더링 원시 기능**에 한정한다.
- 원본 좌표계와 동일한 캔버스에서 렌더한다. CSS의 반응형 크기 변경은 미리보기 외에는 적용하지 않는다.
- 모든 에셋 로딩 완료·폰트 준비 완료를 확인한 뒤 캡처한다. 로딩 중 이미지, 애니메이션, 시간 의존 랜덤 배치를 허용하지 않는다.
- Playwright는 지정 요소만 PNG로 캡처하고 원본 해상도 및 `deviceScaleFactor`를 고정한다.
- 결과에 `template_id`, `template_version`, `outfit_id`, `asset_versions`를 추적 가능하게 연결한다.
- 캡처는 인증된 내부 렌더 경로에서 수행하고 이미지 URL·권한을 검증한다. 외부 임의 URL을 그대로 브라우저에 열지 않는다.

## 8. 품질 게이트 및 인수조건

### Gate A — 원본 재구성
- 네 템플릿 **각각** 동일한 원본 레이어를 재조합했을 때, 기준 이미지(텍스트·오버레이 제거 및 복원 승인본)와 시각적으로 일치해야 한다.
- 원본 캔버스·크롭·주요 레이어 위치·가림 순서·색공간·알파 경계·그림자 보존을 검사한다.
- 픽셀 diff, SSIM 또는 유사 지표, 오버레이 비교 이미지를 산출한다. **합격 수치는 실제 기준본 확보 후 별도 확정**한다.
- 복원된 픽셀 영역은 별도 마스크로 분리해 평가하며 원본 정확 복원이라고 표시하지 않는다.

### Gate B — 의류 치환
- 실제 등록 의류로 각 템플릿의 허용 슬롯을 치환한다.
- 누락·잘림·비정상 스케일·뒤집힌 로고·의류 경계 훼손·비현실적 가림을 점검한다.
- 원본 동일성(색상·패턴·실루엣)과 미적 자연스러움은 별도 평가한다.

### Gate C — 배포 E2E
- 배포된 프론트/백엔드 환경에서 `카드 생성 요청 → 에셋 로딩 → React 렌더 → Playwright PNG → 저장/조회`가 재현되어야 한다.
- CPU·메모리·타임아웃·브라우저 설치 여부를 배포 대상에서 실측한다. Playwright가 기존 백엔드에서 실행 불가하면 별도 작업자/빌드 환경으로 분리한다.
- 동일 입력·템플릿 버전은 동일 결과를 산출하도록 난수·시간·렌더러 버전을 고정한다.

## 9. 비범위 / 후속 계약

- 자동으로 모든 쇼핑몰 의류를 사실적으로 접는 범용 생성 모델 구축은 **본 계약의 확정 기능이 아니다**.
- AI 추천·경험 메모리·코디카드 문구 자동 생성은 다른 도메인 계약에서 관리하고, 본 계약은 렌더링 입력 인터페이스만 정의한다.
- SNS 플랫폼에 자동 게시하는 기능은 본 계약 범위 밖이다.
- 기존 프로젝트의 API/DB 경로 및 컬럼을 확인하지 않았으므로 여기의 논리적 필드 이름을 실제 스키마로 단정하지 않는다.

## 10. 구현 산출물 및 승인 순서

1. `references/` — 4개 원본 및 해시, 오버레이/복원 마스크.
2. `templates/T1..T4/` — 레이어 RGBA, 마스크, SVG, manifest, 승인된 기준 이미지.
3. `components/cards/` — React 4개 템플릿 및 공통 레이어 렌더러.
4. `scripts/render-card.*` — Playwright PNG 생성기.
5. `tests/visual/` — 원본/출력 비교, 차이 이미지, 템플릿별 QA 리포트.
6. `docs/` — 제작 기록, 수동 수정 내역, 한계 및 승인 결과.

**착수 조건:** 기준 이미지의 텍스트·어두운 오버레이 제거본 확보. **완료 조건:** Gate A–C 통과. 구현 전에 현행 `docs/contracts` 및 실제 저장소 구조와 충돌 여부를 확인한다.
