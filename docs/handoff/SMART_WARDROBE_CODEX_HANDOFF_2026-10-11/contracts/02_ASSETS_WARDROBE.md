# CHG-08 — 옷장 디지털 트윈·원본/파생 에셋·조명 계약

> **PoC A1 적용(2026-10-11):** [최신 기준 계약](../POC_CONTRACT_A1.md)이 이 문서의 상충 조항보다 우선한다. 보유 코디 확정=착용1회, LED30초, 관심/혼합 VTON, 홈 미저장 PNG, 구매동기화 제외, 가이드 전용 케어 및 단계별 승인은 A1 기준이다. 아래 종전 정책/기술 경로는 상충 범위에서 이전 기준이며 현재 코드의 구현 완료를 뜻하지 않는다. A단계는 문서만 변경했고 B~G는 별도 승인 전 미착수다.

## 기준 이미지

`references/wardrobe/wardrobe_ui_original.png`: 사용자 제공 **Chrome 화면 스크린샷**, 의류가 이미 배경 픽셀에 들어 있고 미러 UI 텍스트도 포함되어 있다. **빈 옷장 clean plate가 아님**. 소품/소유권/슬롯 자동 판독의 확정 근거로 삼지 않는다.

## 레이어 렌더 구조

1. `wardrobe_frame`: 비어 있는 옷장+서랍/행거의 clean plate. 기존에 포함된 옷을 제거해 배경에 잔존하지 않게 함. 미러 UI 자체는 별도 DOM/컴포넌트로 유지.
2. `stored_items`: DB 현재 위치(`item_id`→ `slot_id`)를 따라 1개 이상의 등록 파생 PNG를 좌표·크기·z-index·원근·가림 순으로 배치. 겹치는 경우 뒤 레이어도 DB 등록 여부 확인.
3. `lighting/highlight`: 찾아낸 아이템의 화면 강조 + 가능한 경우 해당 **구획** Mock LED. LED 제어 해상도가 구획이면 한 벌만 물리 점등했다고 표시하지 않음.

## 이미지 제작 절차

실재 제품 정면 원본 → 원본 provenance/권한 확인 → 투명 배경 컷아웃 → 거치 형태(`hanger-view`, `folded-view`) → 슬롯별 렌더. 원본 상품 사진에 없는 뒷면·측면·진짜 접힘을 무손실 복구할 수 없으므로 합성/생성 파생물에는 `generated/edited`와 `quality_status` 기록. 잘못된 로고·패턴·주름·색상 변형은 반려하거나 단순 컷아웃으로 대체. 이미지 생성 도구 접근이 없다면 계획/프롬프트/품질 시방서를 남기고 검증 불가로 표시한다.

## 동작 및 규칙

- 의류 등록/이동/삭제 후 슬롯 뷰가 최신 DB와 정합.
- `내 옷 찾기`: 한 의류 아이템이 실제 어디 보관됐는지 보여주고 내부 구획에 있을 경우 LED 요청. 외부 위치는 위치 안내만.
- `이 코디 입기`: 등록 의류의 위치 조회 후 필요한 **서로 다른 구획**에 점등 요청. 같은 구획 중복 점등 제거, 자동 소등, 실패/취소/재시도 처리.
- LED Mock/실기기 명령 이력은 API·상태·결과로 구분. 실제 기기에서 성공했다는 주장 금지.
- 계절 반출 제안 승인만으로 화면에서 옷이 사라지지 않는다. 실제 이동 완료·DB commit 후 업데이트.
- 외부 공간 위치 갱신은 기본적으로 사용자 **일괄 이동 완료 확인**, 자동 RFID/카메라 스캔 필수 아님.

## 수용 기준

- DB 아이템 수/위치와 옷장 렌더의 가시 의류가 1:1로 일치. 배경 잔상/중복 아이템 없음.
- 내부 1개 의류 이동·외부 이동·등록·삭제·위치 모름을 각각 검증.
- 조명·강조 영역과 DB 구획 매핑 일치. LED 실기기 미연결은 Mock으로 명시.
- 자산 출처/변환/품질/사용 권한 및 조명 분리 여부를 보고.
