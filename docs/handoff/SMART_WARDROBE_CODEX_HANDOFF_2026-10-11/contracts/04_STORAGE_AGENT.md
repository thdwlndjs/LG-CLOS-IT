# CHG-09 — 보관·회수 선제안 에이전트 정책 계약

> **PoC A1 적용(2026-10-11):** [최신 기준 계약](../POC_CONTRACT_A1.md)이 이 문서의 상충 조항보다 우선한다. 보유 코디 확정=착용1회, LED30초, 관심/혼합 VTON, 홈 미저장 PNG, 구매동기화 제외, 가이드 전용 케어 및 단계별 승인은 A1 기준이다. 아래 종전 정책/기술 경로는 상충 범위에서 이전 기준이며 현재 코드의 구현 완료를 뜻하지 않는다. A단계는 문서만 변경했고 B~G는 별도 승인 전 미착수다.

## 제품 경험

엄마는 가족 모든 구성원의 의류와 보관 위치를 통합적으로 보고, 에이전트는 계절·환경·의류 특성·선호·착용 이력·공간 여유를 보고 **이동과 관리 방법을 제안**한다. 아들은 옷장 안으로 회수된 아이템을 포함해 코디를 만들 수 있다. 단순 날씨 추천으로 끝내지 않고 **현실 위치가 바뀌었다는 확인**을 기반으로 디지털 트윈을 업데이트한다.

## 계절 전환 정책 (`confirmed`)

| 기본 우선순위 | 분류 | 예 |
|---|---|---|
| 여름 의류 반출 우선 | 계절성이 명확하고 최근 사용/일정 예외가 없는 가벼운 옷 | 반팔, 민소매, 얇은 여름 블라우스, 린넨 반바지 |
| 사용 유지 우선 | 여러 계절 활용/겹쳐 입기 가능 | 트렌치코트, 데님 재킷, 가디건, 긴팔 셔츠 |
| 겨울 의류 회수 우선 | 계절 대응 필요성이 커진 방한 의류 | 패딩, 두꺼운 울코트, 방한 니트 |

절대 규칙이 아니라 **보수적 기본 정책**. 온도만 기준으로 모든 아이템을 이동시키지 않으며, 소재·두께·레이어링·최근 착용·기존 코디·선호·공간/케어 환경을 함께 본다. 예외의 근거를 보여줄 수 있어야 한다.

## 상태 전이 (강제)

```text
context_observed → proposal_drafted → proposed → accepted | rejected
accepted → movement_pending → user_confirmed_completed → location_updated
movement_pending → cancelled | failed (location unchanged)
```

- 제안 전 존재하는 등록 아이템, 현재 보관 위치, 목표 공간 여유, 소재·보관 조건, 환경 데이터 시각/Mock 여부 검사.
- 사용자 **제안 수락 시에도** `current_location`은 유지.
- **실제 물리 이동 완료 확인 이후** 원자적으로 `current_location`과 이동 이력을 갱신. 여러 아이템 일괄 확인 중 일부만 완료되었다면 부분 성공을 안전하게 반영/보고.
- 사용자가 보관함에 옮긴 목록을 한 번에 확인하는 것이 PoC 기본. 외부 공간 RFID/비전 추적 고도화는 미래 범위.
- HA 제습기/센서 기기 제어는 기기 권한·실제 기능·지원 API가 입증된 경우에 한함. Mock 센서 데이터로 실제 제습 성공을 주장하지 않음.
- 에이전트가 제안만으로 각 아이템 슬롯을 점유/비워두지 않음. 이동 완료 후 시각화와 추천 가능 목록 갱신.

## 시연 검증 데이터 (P1/P2 설계 항목)

- 계절 변경 날짜와 해당 일/향후 예보, 공간별 온습도, 명확한 여름 아이템 3개 이상, 회수 후보 겨울 아이템 2개 이상(모두 **실재 제품 후보를 검증한 후**)을 포함한 추천 근거 레코드.
- 추천 근거가 실제로 읽히고 재생 가능한 입력 snapshot 저장 계획.
- 여름 아이템은 가족 여러 구성원에 걸칠 수 있으나 엄마·아들 중심 시연.
- 트렌치/데님 재킷/가디건/긴팔에 자동 반출을 권하는 잘못된 과거 시나리오 제거.
- 민소매·반팔 사용이 잦거나 출장/휴가 등 예외 상황일 경우 단순 계절 태그보다 실제 이력/계획을 우선.

## 구현 착수 게이트

이 정책의 **원칙은 확정**이지만 점수 가중치, 센서 최신성, 수납 용량 계산과 HA 명령 실행은 미승인. P0~P2에서 검증 가능한 정책/테스트안을 제안하고 승인 받은 뒤 구현한다.
