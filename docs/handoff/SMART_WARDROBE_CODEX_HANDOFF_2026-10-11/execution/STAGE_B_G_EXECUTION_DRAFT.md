# B~G 단계별 실행 계약 초안 및 승인 게이트

상태: **2026-10-12 B PARTIAL·B-01 시각 승인 완료·B-02 DEFERRED / C~G 미승인**. 기준은 [POC_CONTRACT_A1](../POC_CONTRACT_A1.md)의 B-02 우선순위 조정이다. DEFERRED를 기능 PASS로 처리하지 않는다.

## 공통 강제 절차

각 단계는 **해당 단계 명시 승인 → 구현 → 독립 검증 → 증적 제출 → 사용자 승인 → 다음 단계**로 진행한다. 이전 게이트 PASS만으로 다음 단계를 시작하지 않는다. 실패/미확정 요구는 BLOCKED/PARTIAL과 원인·재개 입력을 기록하고 승인 전 범위를 축소하지 않는다. 각 재개 시 A1 요구 목록과 체크포인트의 잔여 목록 차집합을 확인한다.

기존76/사용자 데이터/승인 왼쪽/기존 동의·권한을 보존한다. 유료 Decart·실물 LED·운영 DB·원격 push·배포는 각 별도 승인이다. 단계 승인만으로 이 외부 작업은 허용되지 않는다. 모든 변경은 로컬 Conventional Commit으로 기록하되 원격으로 보내지 않는다.

각 단계 증적은 requirements.csv(요구ID/상태/구현/테스트/결과/잔여), 변경diff, 데이터/파일 전후 해시, 테스트 원문/브라우저 캡처, 실패/롤백/재개 명령으로 구성한다. 검증자는 승인 원본/manifest/API 계약을 기대값으로 사용하고 구현 출력 자체로 기대값을 만들지 않는다. 검사 실행 실패나 미실행을 PASS로 바꾸지 않는다.

## 의존성 및 게이트 범위

순차 승인 B→C→D→E→F→G를 유지한다. E는 추천 후보/Context/관리 기능을 준비하며 **H01 최종 PNG 완료는 F에 배정**한다. F의 T1~T4 출력물을 E가 먼저 완성해야 하는 순환 의존성을 만들지 않는다. 같은 이유로 D의 새 착용 intent/API를 F 저장카드 UI에서 연결한 W02 최종검증은 F/G다. 각 단계 제출은 자기 단계 소유 요구만 완료로 집계하고 이후 단계 요구를 명시적으로 남긴다.

DB/API 설계는 기존 wearable DTO와 owner/device/asset 관계를 먼저 대조한다. 관심 ID/여러벌같은칸/VTON mixed/card delete/homepreview를 위해 필요한 최소 schema/API 변경은 B/C/F 문서+마이그레이션 diff로 검토한다. A단계에서는 새 경로명이 이미 확정/실행된 것으로 고정하지 않는다. 사용자 제품 정책을 바꾸는 기술 선택은 별도 질문 대상으로 남긴다.

## 중단 및 재개 파일 계약

진행 체크포인트는 stage/기준commit/적용A1버전/승인근거/완료ID/미완료ID/실패증적/다음승인/다음명령을 담는다. 국소 시각 수정이나 로그인 문제로 중단해도 전체 미완료 ID를 삭제하지 않는다. 이전 빈 이력 fixture의 `wear==0` 검증을 생활 시드 완료조건으로 재사용하지 않고 액션별delta를 검증한다.

현재 B-01은 `aed6b48`의 공통 형태35벌·K31·66벌 배치에 대해 사용자 시각 승인을 완료했다. B-02는 **DEFERRED**이며 외부10벌 중복 및 위치 조회 정합성은 미해결이다. 기존 데이터·승인 화면은 유지한다. 후속 구현에서 이동 완료 이력과 물리 위치를 일원화하며 잔여 요구/검증을 삭제하지 않는다.

E단계 승인 시 보관·회수 추천을 위한 Mock 데이터·시나리오 활용 방안을 검토한다. 적용 확정·구현 승인이 아니며 Mock 증적과 실제 DB/Scene/LED/수용량 정합성 증적을 분리한다. 후속 단계 승인 판단 시 B-02 잔여 위험을 명시한다. 이번 문서 수정은 C~G 실행 승인이 아니다.

## 세 질문의 해결 및 게이트 유지

Q-B01은 기존76 ID/데이터·왼쪽을 보존하면서 원본 배치 부족분 신규 적재를 허용하는 것으로 확정했다. Q-F01은 홈2~3개에 서로 다른T1~T4 배분·당일재사용, 수동템플릿 선택 유지로 확정했다. Q-CD01은 마지막 표시 VTON 결과의 요청snapshot으로 확정/카드/관심검사를 수행하는 것으로 확정했다. 선택 변경은 다음 실행 입력이며 표시결과를 소급 변경하지 않는다. 이탈 초기화/늦은결과차단은 유지한다.

이 세 정책 질문은 더 이상 구현 차단 질문이 아니다. 구체 신규수량/상품·소유·에셋·칸 manifest와 기술설계·검증 증적은 각 단계에서 작성할 작업이다. 문서 결정 반영 자체는 단계 게이트 PASS가 아니다. B-01 최종 시각 Gate는 사용자 승인 완료이며 B-02는 후순위 DEFERRED다. C~G는 별도 승인 대기다.
