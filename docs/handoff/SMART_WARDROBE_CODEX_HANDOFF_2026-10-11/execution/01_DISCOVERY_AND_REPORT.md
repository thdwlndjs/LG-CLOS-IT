# 첫 Codex 실행(P0-P2) 상세 작업지시 및 보고 규칙

## P0 저장소 대조 (읽기만)

- 확인: Git 상태, 사용 프레임워크, 실제 docs/FSD/계약, 사용자 프로필 구조, DB 연결 위치(비밀 값 출력 금지), ORM/DDL/마이그레이션, 기존 seed, 이미지 스토리지/서명 URL, 프론트 라우트·컴포넌트, LED Mock, Decart 관련 코드와 구동 조건, 코디카드 담당 팀원의 인계 파일이나 기존 작업 브랜치가 존재하는지도 확인.
- 형식: 기존 구현 위치(파일/행), 계약 요구, 맞음/충돌/없음, 변경안, 리스크, 테스트, 승인 필요 여부.
- 필수 탐지: 기존 `21벌` 하드코딩, 데님재킷/트렌치/긴팔 자동 반출 제안, 코디카드 자동 생성, VTON Mock→실제 표기, 카드 공통 템플릿, 옷장 이미지 옷 픽셀과 DB 동기화 불일치.
- 프로젝트에 실제 없는 파일 경로, endpoint, migration 번호/DB 컬럼은 만들지 말 것.

## P1 시드·실재 제품 후보 조사

- 먼저 가구원/공간/아이템 요구를 시연 목적별로 분류한다. 51개는 `proposed`, 신규 수량 가설은 사용성/슬롯/품질에 근거를 붙인다.
- 가구 공유, 사용 권한, 신발·가방·모자 등 코디카드용 소품, 겨울/여름 이동 후보, 딸/아빠가 등장하지 않아도 엄마의 가족 관리가 성립하는 최소 범위를 분석한다.
- 실제 제품 후보마다 브랜드/모델/품번·출처/색상/소재 및 사진 URL·사용권 상태·원본 해상도 가능성·시연 활용·검증 상태를 기록한다. **엄마 계절 이동 + 아들 코디 + T1–T4 템플릿 검증에 필요한 핵심 제품을 우선** 탐색하고 전체 51개를 아무 근거 없이 채워 완료 처리하지 않는다. 모호한 경우 대체 후보 2개 이내.
- `templates/product_candidates.csv`, `templates/item_plan.csv` 작성; 분류·가격·가용성은 검증한 날짜를 남기고 최신이라고 단정하지 않는다.
- **실제 상품 URL을 조회할 수 없는 실행 환경이면 리서치가 멈춘 이유를 기록**하고 검증되지 않은 물품으로 채우지 않는다.

## P2 에셋/DB/테스트 설계

- `references/wardrobe/wardrobe_ui_original.png`에 의류·Chrome UI가 들어 있음을 보고 clean plate 제작 전략과 마스크 작업량을 분리한다. 실제 이미지 픽셀 좌표는 검증 전 빈 칸.
- `references/card/T1_reference.png` ~ `T4_reference.png`와 템플릿 계약을 읽고 Gate A/B/C를 구현 가능한 태스크로 변환.
- 상품 이미지 → 배경제거 → 행거형·접힘형/카드 파생, 시각 QA·원본 대비 보존 조건·권한 확인·fallback.
- 논리 ERD를 실제 DB ORM/DDL/마이그레이션에 매핑: 어떤 현행 테이블을 재사용하고 어떤 것만 새로 필요한지, 어디서 소유자-기기 관계/이미지 URL 만료 처리/위치 이동 완료를 구현할지 제안.
- 시드 모의 트랜잭션 계획(제품→아이템→위치→환경/이력→추천/코디→카드/LED 로그), idempotency, 테스트용 DB 범위, 백업/rollback 계획.
- P4~P9의 의존성 그래프, 병렬 가능 요소, 테스트 수행 명령(실제 확인 가능한 것만), 단계별 인수조건.

## 보고서 형식 (필수)

`reports/REPO_AUDIT.md`: 실재 파일 경로와 현행 시스템 개요.
`reports/CONTRACT_GAP.md`: ID별 계약과 현행 간 차이, 영향 범위.
`reports/PRODUCT_DISCOVERY.md`: 추천 품목 구성/수량/대체/출처 검증 상태. **우선 엄마 보관·아들 추천·4개 카드에 공통 활용되는 핵심 제품을 먼저 검증**하고 나머지는 검색 범위/미확인 상태를 명시한다.
`reports/ASSET_PLAN.md`: 필요한 원본/clean plate/렌더/카드 파일·권한·품질 위험.
`reports/DB_MAPPING_AND_SEED_PLAN.md`: ERD→현행 스키마, FK·트랜잭션·테스트/롤백.
`reports/IMPLEMENTATION_WBS.md`: 작업 ID, 선행 작업, 추정 난도, 완료 기준.
`reports/DECISIONS_REQUIRED.md`: **사용자에게 실제로 필요한 결정만** 모아서 선택안·추천·근거·미결 시 영향 기록.

각 보고서 최상단: `검사일`, `검사 저장소/브랜치`, `실행 범위`, `신뢰 수준`, `미확인 사항`. 변경 파일 목록과 읽기/실행 커맨드를 기록하고 성공 테스트를 허위 기록하지 않는다.
